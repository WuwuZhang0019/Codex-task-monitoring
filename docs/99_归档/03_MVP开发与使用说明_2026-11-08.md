## 本次交付

## 最快启动

电脑需要安装 Node.js 22.16 或更新版本。已附带构建完成的 `app/dist`，首次试用不需要安装 npm 依赖。

在项目根目录双击 `启动工作台.cmd`。启动器会运行本地服务，并尝试打开浏览器。若浏览器没有自动打开，请访问 `http://127.0.0.1:4318`。请保留命令窗口；关闭窗口或按 Ctrl+C 会停止服务。端口占用时，启动器会提示，不会强行结束其他程序。

也可以在项目根目录的终端中执行：

```bash
node app/server/launch.mjs
```

不要直接双击 `app/index.html` 或 `app/dist/index.html` 试用，应用的保存和 AI 功能需要本地 HTTP 服务。原有 `02_...html` 仍然只是旧交互原型。

## 首次试用

打开工作台后，选择“先用分叉样例试一遍”，核对步骤与依赖，勾选确认后生成路线。选择 M01，填写执行总结和下一步，点击“保存记录”。刷新浏览器或停止后重新启动服务，记录应仍然存在。切换站点或项目遇到未保存修改时，会要求确认是否放弃。

接着创建自己的空项目，选择“导入执行方案”。“载入原执行方案”会读取根目录唯一的 `01_*.md` 文件，但载入本身不会调用模型。也可选择其他 Markdown 文件或粘贴文本。没有模型时，可选“手动录入”；有模型后，再点击“发送并提取路线”。

提取后需要核对项目名称、目标、步骤编号、前置关系、线路、要求、完成条件及原文出处。程序不把数组顺序当作依赖。关系不明确时需要人工核对。编号重复、缺失前置、自依赖或循环依赖会被拒绝，不能生成有效路线。

向已有路线重新导入方案时，本版会创建新项目，不覆盖原路线或已有总结；向空项目导入时，加入该空项目。复杂方案修订合并留待后续开发。

## 配置 AI

在 `app` 中将 `.env.example` 复制为 `.env`，填写模型配置，保存后重新启动服务。不要把真实密钥写进示例文件、源码或聊天消息。

```dotenv
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=填写实际模型名称
OPENAI_API_KEY=填写自己的密钥
```

首版使用 OpenAI 兼容的 `/chat/completions` 接口，要求服务支持 JSON 对象输出（`response_format`）。其他协议、仅支持 Responses API 的服务，以及特定提供方的参数差异，尚未适配。系统环境变量优先于 `.env`。界面中的“模型配置”可查看是否配置，但不是实时凭据连通性测试。

“发送并提取路线”会将原方案文本交给配置的服务；“发送并整理总结”会发送输入文本和选中站点的编号、名称、要求及完成条件。项目存储在本地不等于模型处理在本地，请根据内容敏感性选择服务。

模型返回经过结构、编号、依赖图和原文摘录校验后才进入预览。缺少完成条件时，提示待人工确认，不应擅自补造验收要求。模型超时、错误、输出格式无效时不写入路线。AI 总结只生成建议，确认后放入草稿；仍需“保存记录”才持久化，状态不自动改变。

## 状态与依赖

状态分为未开始、进行中、受阻和已记录完成，由用户手动选择。填写总结不等于完成，手动完成也不代表自动验收通过。只有所有前置及其祖先均已记录完成时，未开始站点才显示“可开始”。如果本站被标为完成但前置仍未完成，会显示前置待完成，不继续解锁后续。

路线按依赖从左到右排列，不支持拖拽编辑。显式线路分行；同一线路在相同依赖层级有并行站点时，会自动分出子行，合流站回到可用主行。路线容器可滚动，最多支持 60 个站点；当前布局不保证任意复杂图都无交叉。

## 数据与备份

默认数据位于 `app/data/projects.json`，每次提交前保留上一版本 `projects.json.bak`。写入使用串行队列、临时文件和原子替换；同一项目采用 revision 乐观锁，旧版本保存会提示冲突，而不是静默覆盖。请让一个服务进程独占数据目录，不要在运行时用编辑器直接修改数据库。

服务重启会重新读取磁盘数据。数据损坏时停止启动并报错，不静默重置。恢复时先停止服务并复制整个 data 目录留存，再检查主文件或从 `.bak` 恢复；备份只有上一版，不替代长期备份。可通过 `WORKBENCH_DATA_DIR` 配置独立的绝对数据目录。

“导出项目”导出该项目已保存的 JSON，不包含未保存草稿，也不包含模型密钥。本版暂未实现该导出格式的一键重新导入；整机恢复应保留原始 data 目录。`.gitignore` 已排除 `.env`、运行数据、依赖和测试产物，没有初始化或提交 Git 仓库。

## 继续开发

前端为 React、TypeScript、Vite，路线为 SVG 连线配合可访问的 HTML 站点按钮。后端采用 Node 内置 HTTP、文件及 fetch API，运行构建版本不依赖第三方 Node 包。后端只监听 `127.0.0.1:4318`，校验本地 Host/Origin，不向局域网开放。Vite 开发端口为 4317，代理 API 到 4318。

开发时在 `app` 目录执行 `npm ci`，随后执行 `npm run dev`，打开 `http://127.0.0.1:4317`。重新交付生产版本前执行 `npm run build`。停止旧的生产服务后再启动开发模式，避免端口冲突。
