# B：展开面板 UI 与多项目分支路线设计方案

日期：2026-11-10

状态：讨论方案；已形成推荐设计，尚未实施

## 1. 推荐结论

采用“项目区块纵向排列，项目内主线与分支横向平行”的路线布局。分支从来源站点向下引出，再转为与主线平行的横向路线；垂直方向用于区分路线，水平方向用于表达各自的步骤顺序。

整体延续现有灵动岛原型的黑色底、圆角、细边框、紧凑文字和站点连线。收起状态保持目前样式与行为，本方案深化下方展开面板。

本文承接同目录 A 指导方案的项目、方案、步骤、分支及状态规则。文档 B 是设计讨论资料，不据此登记执行路线或生成 B-01 等真实站点。下文编号均为示意，不代表项目实际进度。

## 3. 为什么选择平行分支

| 方式 | 阅读效果 | 多分支时的问题 | 建议 |
|---|---|---|---|
| 主线横向、分支步骤一路向下 | 来源直观，适合极少数短分支 | 每条支线改变阅读方向；长分支持续占高，多个项目难以同屏 | 不作为默认 |
| 主线横向、分支横向平行 | 所有步骤按同一方向阅读，便于比较当前进度 | 需要分支折叠和连线避让 | 作为默认 |
| 主线与所有分支全部垂直 | 窄窗口里文字较易排列 | 失去原横向路线观感，多项目面板过长 | 不作为首期布局 |

推荐形式不是把全部路线强行画在同一水平线上，而是“一条路线一行”。主线在上，分支在下，从源站拉一段短的垂直连接线，再沿自己的行向右推进。

**平行是视觉排布，不代表允许并行执行。** 每条路线内部仍按 A 指导方案顺序推进；跨路线能否同时执行取决于实际依赖和授权。横向位置表示路线内顺序，不代表日期、耗时或跨路线同步阶段。

## 4. 展开面板的信息结构

面板分为三层：顶部工具栏、中部项目区块、底部按需打开的站点详情。

```text
                  [ 现有收起条：保持不变 ]
       ┌──────────────────────────────────────────────┐
       │ 项目路线   全部项目 / 当前项目   定位当前  固定 收起 │
       │ 最近同步 14:32 · 已连接                         │
       ├──────────────────────────────────────────────┤
       │ ▾ 项目一 · Codex 任务监测器                     │
       │   1 条执行中 · 1 个阻塞 · 2 个待确认分支          │
       │                                              │
       │ 主线 A    A-01 ── A-02 ── A-03 ── A-04         │
       │                     │                        │
       │ 分支 C              └── C-01 ── C-02 ── C-03  │
       │                          │                   │
       │ 待规划                   └── 虚线开放端         │
       │ 已结束分支 3 条 · 展开                          │
       ├──────────────────────────────────────────────┤
       │ ▾ 项目二 · 建筑规范知识库                       │
       │ 主线 A    A-01 ── A-02 ── A-03                 │
       │ 另有 4 条分支 · 查看                            │
       ├──────────────────────────────────────────────┤
       │ 选中 C-02 · 异常恢复验证 · 执行中                │
       │ 最近进展……          查看详情   打开关联会话      │
       └──────────────────────────────────────────────┘
```

此图只表达层级与方向，间距、线条及按钮以实际原型调整。项目间不绘制跨卡片长连线；存在跨项目依赖时，在站点详情显示目标项目与步骤入口。

### 4.1 项目区块

一个区块对应一个工作台业务项目，不按 Codex 侧栏文件夹拆分。同一业务项目关联的多个会话文件夹、主线和分支都归入同一区块。

项目标题行显示：折叠按钮、项目名称、执行中数量、阻塞数量、待确认分支数量。标题下用一行短句说明当前关注事项，例如“主线 A-03 等待权限分支完成”。

默认按用户固定顺序展示项目；未设顺序时按登记顺序。状态更新不自动重排项目，避免用户阅读时区块跳动。提供“只看有待办项目”筛选，筛选时说明隐藏了多少项目。

折叠后保留项目名称、当前步骤和异常计数。已完成项目可收起，但未处理分支仍明确计数，不能显示为整体完成。

### 4.2 同一项目有多条主线

同一项目允许多个独立方案，每个方案形成自己的路线组。主线 A 与主线 D 分组显示，各自分支紧随所属主线。没有来源关系的方案不伪装为分支，也不为了连成一张图而补造依赖。

路线组左侧保留简短标签，例如“主线 A · 桌面接入”“分支 C · 异常恢复”；完整方案名、来源和文档入口放入详情。

## 5. 分支与连线的具体规则

### 5.1 已规划分支

主线站点下方引出细连接线，分支首站放在来源站的右下方，随后从左到右排列。连接线使用圆角折线，转折处留白，不穿过站点文字。

每条分支行显示两个身份：永久分支编号和承接方案。例如：

> 异常恢复 · 分支 A-02-01 → 方案 C · 来源 A-02 · 阻塞 A-02

分支内步骤显示 C-01、C-02 等编号。不能把 A-02-01 画成一个正式步骤，也不能在形成方案后丢失它与来源站的关系。

同一来源站产生多个分支时，下方分行排列。共享一小段向下的来源连接线，再分别引出；每一行均标明来源与阻塞关系，不依赖颜色识别。

### 5.2 未规划分支

从源站引出短虚线，末端显示开放提示条，例如“A-02-02 · 性能优化 · 待确认”。末端不使用正式站点圆点，不显示虚构的步骤数量或百分比。

待确认与待规划分别显示文字。点击打开分支说明及关联会话入口，不因点击线路就视为用户批准规划或执行。方案形成后，原提示条原位转为正式分支路线，保留固定分支身份。

### 5.3 深层分支与大量分支

首次打开项目，默认显示主线及最多 3 条直接分支。优先选入阻塞分支、执行中分支、待确认分支，再按登记顺序补足；用户展开或阅读后，更新只改状态与计数，不动态换行。

超过 3 条时，显示“另有 8 条分支，其中 2 条阻塞、3 条待确认”。该入口提供本项目分支列表，按状态筛选并定位来源；不能只显示一个没有异常信息的“更多”。

第二层及更深的分支默认在来源站显示“子分支 3 · 阻塞 1”。点击进入局部聚焦视图，顶部显示“项目 → 主线 A → 分支 C”，将 C 暂作为当前阅读主线显示其直接子分支。这样层级可持续增加，不让画布无限缩进。

返回全图时恢复之前的滚动位置、折叠状态和选中站点。已结束分支默认汇总为“已结束分支 N 条”，保留查看历史入口；返工重新打开后恢复为活动分支。

### 5.4 回归主线与依赖

- 只有明确记录了接入目标，才绘制回归线；不把所有分支末端自动接回下一站。
- 阻塞分支在来源站和分支行同时显示“阻塞”标记。
- 分支完成只表示分支完成；来源步骤仍按自身验收状态展示。
- 默认突出选中路线及其直接来源、回归关系，其他连接降低亮度。
- 回归线跨越多行或产生交叉时，使用“回到 A-03”入口，并在选中时显示完整关系，避免常驻密集交叉线。
- 已规划步骤之间用实线；未规划开放线用虚线。依赖关系额外标注文字或箭头，不与步骤顺序线混为一谈。

## 6. 视觉风格与尺寸建议

以下为展开态设计起点，不是已经实现或已验证的参数。

| 元素 | 建议 |
|---|---|
| 面板底色 | 延续现有 `#141416` |
| 项目区块 | 略亮底色 `#1B1B20`，细边框 `#303034`，12px 圆角 |
| 选中区块或站点 | 淡紫灰描边，轻微底色变化，不使用大块高饱和背景 |
| 项目间距 | 12px，区块内边距 16px |
| 标题 | 项目标题 14–15px，站点标题 12px，辅助信息 11–12px |
| 路线 | 主线约 3px，分支约 2px，分支来源线更弱 |
| 站点 | 可见圆点约 12px，点击热区至少 28×28px |
| 站点间距 | 约 112–128px，编号、短标题、状态分层排列 |
| 路线行距 | 约 88–100px，避免上下两行文字与连线重叠 |
| 展开宽度 | 建议 960 DIP，最多取工作区宽度减 32 DIP |
| 展开高度 | 建议上限 640 DIP，同时受顶部条下方可用工作区高度约束，底部留 16 DIP |

用轻微底色差和留白分项目，不为每个项目分配鲜艳背景。主线与分支用线宽、行标签和来源关系区分；颜色优先服务状态。

现有原型采用“红灯＝验收通过、绿灯＝正在执行”。为保持熟悉感，本轮延续该语义，并始终配“✓ 已完成”“● 执行中”等文字或图标；已阻塞建议琥珀色警示标记，待执行与已取消使用灰色并分别标注。不要悄悄将红色重新定义为失败，造成展开态与收起态相反。

标题过长时最多两行，完整名称在点击详情后显示。完整编号不因标题截断而消失。连接中断以“连接中断 · 最后更新 HH:mm”提示，不把所有站点改成失败。

## 7. 滚动与聚焦

纵向只保留面板主体一个滚动区域，工具栏固定；项目区块不再各自增加纵向滚动条。展开项目后可以自然向下阅读，不出现滚轮被多层容器反复截获的情况。

横向以项目为单位滚动，该项目主线与分支共享横坐标与滚动位置；左侧路线标签固定。项目之间各自保留横向位置，互不影响。

路线超过可用宽度时保持字级与站点间距，允许横向滚动，不把几十站压缩到不可读。提供“定位当前”和左右溢出提示；“定位当前”滚动至选中路线的执行中或阻塞站点，多个候选时先给出选择。刷新数据不强制移动视口。

小屏仍保留横向路线，减少同时可见站点数。首次以一个主要项目展开、其他项目折叠的方式减少高度；记住用户之后的选择。项目折叠、分支折叠与局部聚焦足以控制规模，首期不增加自由缩放和任意拖拽节点。

## 8. 站点详情与日常操作

单击站点，在面板底部打开约 140–180 DIP 高的简要详情区，占用面板内部空间，不遮住路线；显示编号、标题、状态、最新进展、最后更新时间和阻塞来源。长内容通过“查看详情”进入完整阅读视图，显示执行内容、验收要求、历史与证据。

提供“打开关联会话”“查看方案”“查看交付物”等与该站直接相关的入口；关联不存在时明确显示未绑定。打开目标失败时保留当前面板并说明原因，不假装已跳转。

用户正在点击站点、选择分支或阅读详情时保持展开；关闭详情后恢复原来的固定或悬停状态。新事件以工具栏下的一行提示出现，用户点击后定位相应项目与站点，不主动切走正在阅读的项目。

键盘支持聚焦项目折叠按钮、站点和操作入口，并显示清楚焦点描边。Esc 在面板拥有焦点时先关详情、再退出局部聚焦、最后收起面板；非焦点桌面状态始终可用明确的收起按钮。

空项目显示“尚未收到路线”；筛选无结果显示“当前条件下没有路线”并提供清除筛选入口。同步失败、业务阻塞与未绑定会话分别表达，不能混成一个红色错误状态。

## 9. 典型使用场景

| 场景 | 预期画面与操作 |
|---|---|
| 3 个项目同时推进 | 每个项目一个区块，项目头可扫读当前步骤与异常数量 |
| 同一项目有 2 条独立主线 | 项目内两个路线组，分支各自归组，不虚构连线 |
| 一个站点有 8 条分支 | 主视图最多显示 3 条，剩余数量及阻塞计数可见，一次点击打开列表 |
| 分支又产生分支 | 来源站出现子分支计数，点击进入局部聚焦，不无限撑高全图 |
| 一个分支尚未形成方案 | 虚线开放端加待确认或待规划文字，不出现正式假站点 |
| 主线有 30 个步骤 | 横向滚动与定位当前，站点保持可读尺寸 |
| 阻塞分支完成 | 分支标为完成，来源站保留自己的状态和验收信息 |
| 主线完成、仍有独立分支 | 项目头显示“主线已完成，另有 N 个待处理分支” |
| 用户阅读时收到其他项目更新 | 保持视口与选中项，仅更新状态和事件入口 |
| 多个项目都有 A-01 | 详情始终带项目名称，以项目与步骤固定 ID 定位 |

## 10. 下一步原型范围

建议下一轮先在现有顶部面板原型上制作展开态效果，使用明确标识的模拟数据，覆盖三个项目、同源多分支、深层分支、待规划开放端和长路线。保留当前收起态，先确认阅读体验，再单独制定真实数据接入与状态持久化的执行方案。

原型视觉复核重点为：项目边界是否清楚、分支来源是否可追溯、当前站与阻塞是否容易找到、折叠后异常是否仍可见、长编号和长标题是否重叠、小屏与显示缩放下是否可读，以及展开收起是否影响顶部条稳定性。
