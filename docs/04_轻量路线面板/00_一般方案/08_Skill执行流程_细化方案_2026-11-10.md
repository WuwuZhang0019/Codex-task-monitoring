# Skill 执行流程细化方案

日期：2026-11-10

状态：新路线模块细化方案，待实施

本文按已确认需求拆分模块职责、接口和验收要求。原指导方案及 UI 设计作为需求来源，本文与其他六份细化方案共同组织后续开发。

## 目标与职责

提供一个流程入口，指导 Codex 读取原方案、提取路线、组织会话并按时调用 MCP。原方案编号随资料保存，会话命名与原文步骤建立映射。

## 开发内容

1. 核对现有 `workbench-handoff` 的职责、工具使用和规则，确定复用或修订范围，形成单一入口的使用说明。
2. 登记流程读取原文及来源版本，提取步骤、内容、验收、依赖和工作树分配。含糊或缺失的前置保留待确认，提交结构化草稿并处理校验反馈。
3. 会话组织流程根据实际任务分组分配 A、B、C，生成文件夹与会话名称，调用可用的绑定和宿主操作能力。
4. 开始流程读取最新快照，核对绑定、目录、分支和前置，提交本次执行与当前步骤开始事件。
5. 过程流程在步骤开始、验收通过、阻塞、恢复、取消或返工时上报。普通调试和自动重试继续记录在当前步骤。
6. 结束流程提交结果、验收证据、未完成事项及相关步骤快照，读取保存回执，明确本次结束原因。
7. 接续流程读取现有状态，查询未确认事件，沿用同一次逻辑执行标识，处理版本冲突后补报。
8. 计划外独立事项记录来源及阻塞关系，按用户授权处理规划和执行范围。

## 与其他模块的约定

Skill 使用 MCP 已声明的能力，保存回执决定同步结果。路线模块检查业务状态，存储模块处理可靠提交。无法上报时说明待同步内容并留下可恢复记录。

## 验收

在真实聊天中分别验证首次登记、单会话多细分步骤、工作树分配、正常结束、等待用户、阻塞恢复和新会话接续。检查原文步骤未被错误重编号，工具调用记录能对齐实际工作。

## 交付

Skill 源文件、必要参考资料、安装或插件打包说明，以及真实调用记录。具体工具名在 MCP 契约确定后绑定。
