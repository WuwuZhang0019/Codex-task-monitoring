# 数据存储与恢复细化方案

日期：2026-11-10

状态：开发细化方案，待实施与现状核对

本文按已确认需求拆分模块职责、接口和验收要求。原指导方案及 UI 设计作为需求来源，本文与其他六份细化方案共同组织后续开发。

## 目标与保存范围

持久化方案、原文步骤、依赖、状态、执行批次、事件、会话和工作树关联、证据引用及 UI 偏好。沿用现有存储设施前先核对其事务和恢复能力。

## 开发内容

1. 定义数据版本与固定 ID，原文编号、会话组织编号及文件夹序号分别保存。
2. 将业务更新、版本递增、事件记录与幂等结果纳入同一提交边界，读取仅返回已提交状态。
3. 保存执行历史、阻塞与取消原因、返工和方案修订，支持按方案、执行或事件回查。
4. 写入失败保持一致的可读版本。重启时恢复已提交记录，检查关联完整性。
5. 保存发送侧可恢复的待同步事件，使用原事件 ID 重试。服务端记录收到时间，发生时间依据上报资料保存。
6. 响应丢失通过事件查询判定提交结果，连接恢复先读取版本再补交。
7. 为旧数据建立迁移与备份流程，保留旧编号及来源映射。缺失关联显示待绑定，未知历史时间保留未知。
8. 定义备份位置、恢复入口、诊断日志及敏感字段脱敏，恢复后检查方案版本、事件及关联一致性。

## 接口与依赖

服务于路线、MCP、会话关联和 UI 偏好模块。提交接口统一返回保存版本和事件结果。

## 验收

覆盖保存后重启、提交中断、磁盘写入失败、重复重试、响应丢失和备份恢复。核对步骤、历史、版本和幂等结果一致，未收到结束事件时保留最后状态及待确认提示。

## 交付

存储模型、迁移和恢复实现、备份恢复说明及故障注入记录。
