## 3. 身份与可信边界

工作台 projectId、folderId、taskId、stationId、planId、sourceId 均引用本项目真实实体。外部 Codex 项目身份、目录组与内部文件夹分开。外部源键由 provider、hostId、dataRootId、sessionId 组成，threadId、父会话及 turnId 按实际来源保存。标题和 cwd 只用于显示与匹配候选。

`scope` 固定项目、文件夹、任务、站点、方案、来源、bindingId/bindingRevision、executionId。服务验证 scope.projectId 与顶层 projectId 相同，引用处于同一授权，站点属于任务，任务属于文件夹，来源绑定适用当前方案和站点。executionId 为同一次逻辑执行的稳定标识，重试和跨聊天续接保留它。新执行经服务登记后才取得有效身份。

客户端只提交 actorDeclaration。sourceTrust、核验角色、授权主体和审计身份由服务端生成。客户端传入 sourceTrust、reviewer、正式批准或关闭字段按 schema 拒绝。sourceTrust 使用 declared、userConfirmed、hostObserved，附实际依据和缺失原因。本地索引确认来源存在只证明存在性。探测响应为 declared，选定聊天的用户确认单独记录。

绑定由已认证 UI 生成稳定 ID 及版本，含确认时间、确认记录和撤销时间。fork、新聊天、换任务、方案改变、工作树迁移或分支变化都重新检查适用性，历史执行保留原绑定版本。旧数据缺少绑定时展示待绑定。

`workContext` 保存仓库 ID/根、工作树、分支、HEAD、detached、dirty、内容指纹、时间及关联来源/执行。未知历史字段为 null 并附 verification=unknown。服务可在授权目录独立核对，AI 自述为 declared。dirty 交付的证据至少包含内容指纹。

## 4. 草稿、确认与权限

草稿保留原文、sourceHash、出处和候选结构。原始/当前目标、版本/日期、终点、完整步骤声明、站点/依赖/验收、需求覆盖、字段 provenance 和候选/暂停事项均独立保存。缺少目标等信息时允许 null，问题清单负责集中补齐。candidate 中尚未明确的站点可暂不列入，发布时必须检查原文路线声明和覆盖缺口。

来源摘录必须真实存在，字符位置按 UTF-16 记录，系统生成 ID 和用户修订各有来源。发布时检查稳定编号、任务唯一归属、无环且双向一致的依赖、所有必需验收与终点、原文步骤完整性。Schema 数组上限与既有 60 站、原文 500000 字符兼容。请求总量继续受 2MB 限制，超限明确拒绝。

普通插件凭据可以读取授权项目、保存/校验草稿、登记执行/修复/阻塞、提交回执和核验候选。发布必须同时具有特定草稿/创建意图授权及服务端确认凭据。首次创建授权绑定 creationGrantId，成功后收紧为实际项目。已有基线变更必须展示差异，confirmationDigest 绑定草稿 revision、原文 hash、差异、当前项目 revision、授权及有效期，变更或撤销后失效。

正式核验批准由已认证工作台核验入口或受控验证器执行。候选与 receiptLog.reviews 分库存储，客户端自述 checks=passed 仍为候选。受控验证器的命令和目录来自已发布授权配置，记录真实运行身份、命令、环境、退出码、产物及指纹。MCP 参数里的任意命令保持资料内容。

## 5. 版本、幂等与可靠提交

所有业务写入都携带 schemaVersion、expectedRevision、idempotencyKey 和来源声明。expectedRevision 针对项目聚合版本，草稿自身 revision 另存。多处版本冲突均明确返回 currentRevision，重新读后由调用者决定修正。开始前重新检查依赖与绑定。

幂等索引键为已认证授权主体、projectId、工具名、idempotencyKey。语义 hash 使用排序 JSON，对象键排序、数组保序，覆盖全部业务参数，排除传输 JSON-RPC ID 和重试时间。跨授权主体或项目无法查询结果。同键同内容返回首次已提交结果及 requestId，同键异内容返回 IDEMPOTENCY_CONFLICT。已提交旧请求的重放先查询幂等索引，随后再判断新写入版本。授权撤销和停止标记优先限制新的操作，历史结果只在仍有效的读取授权内查询。

单领域所有者将业务结果、事件、审计及幂等结果作为同一逻辑事务。采用持久化 prepared 记录、完整数据 staging、持久提交标记及读取可见性门禁。项目列表、详情、模型、monitor、outputs、MCP 查询均遵守门禁。崩溃恢复按事务记录补齐同一提交或保持不可见，失败时保留原数据和诊断。U02/U03 必须用故障注入证明实际耐久性，现有逐文件 rename 的代码证据只覆盖其原范围。

响应丢失、取消或超时的写入先标为 unknown，通过 requestId 或原 idempotencyKey 回查 committed/rejected/pending/unknown。只有明确未提交才能新建逻辑操作。未知状态保留原键并查询或重试原请求。只读探测请求无需幂等键，每次读取 requestId 是实际请求身份。

## 6. 修复、恢复与全局判定

RepairCase/RepairAttempt/ReturnAnchor/ResumeContext 的字段定义见 schema。首次交付不算修复轮数，实际开始的新尝试追加 attemptId/executionId。同一请求重试、同次换聊保持一轮，已开始中断计入并单列。案例合并/重开保留计数来源。解决候选进入 pendingReview，正式解决由有效核验计算。

ReturnAnchor 记录原站、适用方案、条件、依赖、合法后继、合流及生成时 revision。每次恢复均重读当前方案、绑定和全部依赖。ResumeContext 同时返回总目标、当前站、未决修复、最近有效交付、等待对象及回归位置。

disposition 与 basisRevision 来自同一读快照。允许 continue_station、continue_repair、wait_dependency、wait_verification、handoff_successor、merge_review、end_task、end_project。A—G 继续沿用 outputs/receipts/monitor 的含义。换聊后过期建议只供追溯，新版本重新计算。合法后继可开始与后继已开始分别登记。连续两轮同条件无进展时提示重新评估，具体阈值需用户确认。

所有业务响应包含 schemaVersion、ruleVersion、requestId、status、basisRevision、supportedCapabilities、disposition、sourceTrust 和原因。错误码见 schema，协议错误用 JSON-RPC 错误，业务拒绝用 isError 与结构化错误。未知版本明确 UNSUPPORTED_VERSION，能力缺失返回 UNSUPPORTED_CAPABILITY。新增可选字段需兼容版本规则，破坏性变更升 major，Skill 遇到未知 major 停在兼容核对。

## 8. 桌面与运行契约

生成器固定 create-tauri-app 4.7.5，正式宿主选择 react-ts 模板，包管理器 npm。U02 在隔离目录生成并审查差异后接入 app。已有面板为同版本 vanilla-ts 模板，React 集成差异交接 U02。前端/Rust 依赖以实际锁文件为准，探测使用 Tauri 2.11.6、wry 0.55.1、Node 25.5.0。正式发行须打包固定 Node 运行组件、服务/模板/MCP 资源及许可，WebView2 前置由安装器检查，运行烟测归 U02/U07。[官方工程入口](https://v2.tauri.app/start/create-project/)

现场存在生成器版本不一致。npm 封装及 win32-x64-msvc 平台包均为 4.7.5，直接调用其文件的 `--version` 返回 4.8.0。平台二进制 SHA256 为 `4CCE9F9EAB2A7590E2C3DC70D2C51A5F593AC3584B2231F3CE783359FAA6B12E`。本契约同时固定分发包、实际自报版本与该指纹，U02 生成前复核同一产物。原因待核实，记录位置为 generator-fixed-version.log 和 generator/package-lock.json。

正式 identifier 固定为 com.codextaskmonitor.workbench，数据根采用 Tauri app_local_data_dir 下的 data 子目录，界面展示实际解析路径。资源目录只保存发行资源。旧 app/data 的迁移须先确认真实写入者并停写、整目录备份、清单及 hash、复制测试、迁移验证、显式切换，失败回到原目录及原版本。此路径选择为本次契约决定，待核验。

每个数据根持有 OS 级排他锁，锁覆盖桌面、无界面服务和 MCP 启动路径，进程退出由 OS 释放。PID 用于诊断。主/浮窗和桥只连接所有者。私有回环用动态端口，发现记录包含 ownerGeneration、PID、版本及端点，凭据为至少 256 位随机值，通过受控环境或每用户私有文件传入。凭据不进入 URL、日志、UI 持久化或插件包。

正式私有入口保留 Host/Origin/体量校验并逐次验证工具及项目授权。Tauri invoke 仅允许白名单路径/动作。跨进程锁、ACL、授权撤销与全部直接写入口防护须由 U02/U04 实测。U01 owner 是固定只读私有 facade，输入服务和模型读均复用现有 store/model-store；它的能力仅限隔离样例。

主窗口关闭到托盘。显式退出先拒绝新写入、处理在途事务并持久化停止标记，桥后台重试暂停。主动重开/恢复清除停止标记。异常断开有界退避，先检查原请求状态。建议初始退避 250ms/500ms/1s/2s/5s，上限 5s，未知 ownerGeneration 重新握手。正式启动预算 10s、MCP 握手 10s、读工具 5s、写工具 30s，宿主配置工具预算 45s。超时写入走 unknown 回查。U01 owner 读取预算 3s、客户端握手 10s，正式预算仍需 U02/U04 验证。[宿主 MCP 超时配置](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

## 9. 插件和 hooks 契约

本机 CLI 已接受根 portable plugin.json、mcp.json，实际将 `${PLUGIN_ROOT}` 解析为缓存内绝对路径，cwd 同样解析。单一 Skill 从 skills/workbench-handoff 复用，安装时核对与源文件 hash。U01 开发包仍依赖本机 Node，发行包无全局 Node 的要求由 U02/U07 实测。

插件安装、桥就绪、实际调用、项目授权、目标聊天可调用、Skill 可见、hooks 信任/实收分别登记。当前聊天安装前已经发现用户级 Skill，插件 Skill 的既有聊天刷新和诊断聊天调用仍待验。CLI 安装接受清单只覆盖格式/安装及路径，真实聊天工具发现需保存该聊天的实际调用。[官方插件打包](https://developers.openai.com/plugins/build/plugins)

本次没有接入 hooks 处理器，实收事件为零，覆盖未知。后续按目标宿主逐事件验证 SessionStart、UserPromptSubmit、Pre/PostToolUse、Stop、Interrupt、SessionEnd，保存事件载荷、信任状态、编排与执行位置。命令型、插件和云端编排覆盖分别记录。已支持环境的观察 helper 中性退出，Stop 不返回继续/阻止决策。投递 500ms、有界 spool 10MB/24h、活动信号过期 120s 等来源方案参数继续适用，由 U04 验证。[官方 hooks 环境与信任规则](https://learn.chatgpt.com/docs/hooks)
