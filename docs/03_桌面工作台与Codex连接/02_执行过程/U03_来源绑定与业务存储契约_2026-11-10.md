## 来源绑定接口

领域服务的 binding 保存 U01 binding 的全部字段。UI 确认入口接受已有聊天 sourceId、任务、可选站点、当前 planId，以及 provider/hostId/dataRootId/sessionId/threadId、确认依据。服务生成 bindingId、bindingRevision、时间及 userConfirmed 标签。存在性和真实宿主身份的核对由 U04 接入承担。固定样例声明单独标记，不生成 hostObserved。

撤销追加撤销时间和版本。执行 scope 必须与 binding 的项目、文件夹、任务、站点、方案和来源匹配。工作树/分支变化要求重新确认。跨聊天接手保留 executionId 和 attemptId，追加接手历史，旧来源迟到结果保留为历史候选。客户端不能写入正式批准、来源可信级别和执行历史。

U03 提供私有 UI HTTP 业务入口和可复用领域函数。U04 将九工具映射到同一函数，授权主体、项目/创建授权和撤销由该接入层提供。当前 MCP 发现仅有 project.read.probe，人工台账为本轮开发进度权威位置。

## 持久化与版本

服务取得 U02 数据根锁后，使用单一聚合快照保存 projects、models、drafts、请求结果、事件和审计。所有正式读取入口使用已提交快照。持久 prepared 内容及哈希、提交标志、主快照按顺序同步到磁盘。提交标志前失败保留上一快照，标志后失败拒绝继续服务并要求重开恢复同一事务。

旧 projects.json、models、legacy、备份原字节保留为迁移来源。首次聚合迁移先验证完整旧数据，保留不可覆盖的迁移快照。后续 aggregate.json 为权威数据，完整目录备份包含事务文件。禁止运行旧版本写入已切换目录。

幂等键绑定可信调用主体、项目/创建目标、操作及业务参数。重放先于 revision 判断，同键异内容拒绝。响应丢失使用原键查询或重放。普通旧入口保留既有 revision 语义，新业务入口统一使用模型聚合 revision。草稿 revision 独立。
