## 1. 本次目标与结束条件

根据用户选定的 Openbar README 中 Windows 演示，独立实现顶部紧凑条与展开面板之间的连续形变。保留本项目的路线缩略图、展开路线和固定模拟数据。

## 4. 交互与动效规格

### 4.1 几何和内容锚点

- 紧凑态基准为 600×38 DIP，展开态基准为 920×560 DIP，尺寸遵守目标显示器工作区宽高各减 32 DIP 的上限。
- 主体顶部锚定工作区上沿，水平中心固定在选定显示器工作区中心。
- 顶部摘要层宽度固定为紧凑态实际宽度，高度固定为 38 DIP，始终相对宿主中心定位。下方内容起点固定在顶部层下沿。
- 下方路线按实际展开宽度一次布局。动画只改变外形的可见范围，文字、站点和卡片保持正常比例。滚动仅发生在下方内容区。
- 紧凑态七站缩略图、当前站、执行数量和未读数沿用当前原型。动效期间收到业务更新时先暂存显示快照，动效稳定后一次应用，避免将文案长度变化混入位置稳定性检查。

### 4.2 自定初始参数

下表为本项目初始设计值，依据原型观感调整，逐次记录变更。

| 项目 | 初始值 |
|---|---|
| 悬停展开延迟 | 180ms |
| 移出后收起延迟 | 350ms |
| 主体展开 | 280ms，`cubic-bezier(0.22, 1, 0.36, 1)` |
| 主体收起 | 240ms，`cubic-bezier(0.4, 0, 0.2, 1)` |
| 展开内容入场 | 主体展开后延迟 70ms 开始，160ms 内透明度从 0 到 1、向上位移 6 DIP 至原位 |
| 收起内容退场 | 开始收起时在 100ms 内淡出，主体从当前外形同步回缩 |
| 底部圆角 | 紧凑态 18 DIP，展开态 20 DIP，随主体连续插值 |
| 事件自动收起 | 触发后 8 秒，悬停或固定时保持展开 |
| 减少动态效果 | 去除位移动画，状态切换缩短至 0—80ms，保留相同最终状态与交互区域 |

第一版采用无过冲缓动，要求背景边界、顶部锚点稳定。若用户确认需要弹性，再在同一主体几何驱动器内调整缓动，限制过冲到宿主预留边界之内。

### 4.3 状态机与中断

| 状态 | 输入与动作 |
|---|---|
| `compact` | 鼠标停留 180ms 后进入 `opening`；点击时登记固定并进入 `opening` |
| `opening` | 从当前几何到展开几何；离开后仍遵守 350ms 延迟，可从当前进度反向进入 `closing` |
| `expanded` | 鼠标离开且无固定或通知保持时进入 `closing` |
| `closing` | 从当前几何回缩；重新进入可立即从当前进度反向展开 |

固定标记、鼠标是否在实际可见区域内、通知保持截止时间作为独立状态。任意时刻只有一个有效几何动画实例。新目标从当前采样进度续接，旧实例的完成回调和延迟任务必须失效。重复请求同一目标保持当前动画进度。

鼠标从顶部移动到已展开内容时属于同一交互面。模拟执行结束、验收通过沿用当前状态语义；事件面板复用同一主体动效。减少动态效果、重置、退出、动画中切换目标和通知计时均经过同一个控制器。

## 5. 技术实现设计

### 5.1 固定宿主和内部形变

原生窗口保留一个面板宿主，初始化时按展开上限分配尺寸并定位。窗口常驻顶部、透明外缘、无标题栏、非焦点模式。日常展开和收起只更新内部形状及原生可见区域。显示器、DPI 或工作区发生变化时，在受控重定位流程中重新计算宿主。

前端采用以下分层。

1. 透明固定尺寸画布。
2. 以画布顶部中心为基准的连续黑色背景轮廓。
3. 固定坐标与尺寸的顶部摘要层。
4. 固定展开布局的路线和事件层，按第 4 节控制可见范围、透明度及小幅位移。

可采用 `clip-path: inset(...)` 与圆角参数从紧凑轮廓插值到展开轮廓，正文在裁剪层内部保持展开布局。顶部层位于独立布局层，避免宽度插值、滚动条或正文换行改变其坐标。优先使用现有 TypeScript、CSS 和 Web Animations API，是否新增动画库由 FX01 的实测决定。[Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate)

### 5.2 实际命中区域与窗口裁剪

固定宿主内部的大块透明空间必须允许用户操作下方软件。仅用 CSS 透明度和 `pointer-events` 无法据此认定原生窗口已经穿透。

Windows 首选用 `SetWindowRgn` 配置当前面板轮廓对应的窗口区域。区域坐标按物理像素计算，并核对窗口外框与客户区坐标差。成功交给系统的 HRGN 由系统管理，失败时释放本次创建的对象。[SetWindowRgn 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowrgn)

实现时必须满足以下顺序与约束。

- 初次显示前先应用紧凑态区域，避免闪出整个展开宿主。
- 动画期间用同一几何进度生成前端轮廓及原生区域。禁止预先把整个展开矩形长期设为可交互区。
- 原生区域命令携带递增 `transitionId` 和 `frameId`，在窗口线程串行执行。单个调用在途时只保留最新待处理几何，拒绝旧动画和旧帧覆盖新状态。
- 前端暂停在当前进度时，原生区域应能应用同一帧。允许的取整保护边界上限为 1 个物理像素，不能留下透明大矩形。
- 动画完成后下发并确认精确终态区域，清除待处理旧帧。主线程繁忙、IPC 失败或取消时回到已确认的可见状态并显示可诊断错误。
- FX01 必须验证 WebView2、窗口区域及页面绘制的实际同步。若出现裁边、白闪、输入阻挡或悬停丢失，在 FX01 修正并复验后再继续；实现方式的可行性以本机证据为准。

`SetWindowRgn` 可能触发窗口位置相关消息，因此测试需记录实际位置和尺寸，分别判断宿主移动与窗口区域更新。日常动效路径应没有主动改变宿主尺寸或位置的调用。

### 5.3 非抢焦点与环境变化

悬停、模拟事件及自动收起保持前台软件和输入目标。原生显示调用使用非激活方式并验证实际焦点。显式退出仍使用原有入口。工作区或 DPI 改变时，取消当前过渡、更新尺寸和坐标、应用稳定终态后恢复交互，避免复用旧屏幕几何。

小屏基准取 `compactWidth = min(600, workWidth - 32)`、`expandedWidth = min(920, workWidth - 32)`、`expandedHeight = min(560, workHeight - 32)`。顶部摘要按优先级省略长文字，七站缩略图保留；内容超出可用高度时由展开内容区滚动。各缩放下文字可读性需实测。
