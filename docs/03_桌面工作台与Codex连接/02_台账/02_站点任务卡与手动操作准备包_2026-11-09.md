## 1. 派发前填写

每次复制本站卡及第 3 节执行模板，填写执行 ID、聊天、工作树、分支、HEAD、方案/台账提交版本和前置证据。在主台账登记实际发送位置与时间。执行者汇集证据，指定核验聊天复核实际结果；涉及体验或范围决定时由用户确认。每个核验角色在派发时记录实际聊天或人员。

## 2. 八站任务卡

以下清单是派发检查入口，各专项完整验收仍按总纲引用执行。条件 ID 固定，调整条件时保留原文与修订依据。全部条件初始待执行。

### U01 现场与契约验证

前置为总方向、六专项方案和总纲。范围包括宿主、读取、接入、原生可行性与统一契约。交付为现场记录、能力表、真实工具回执、原生探测证据、schema 及缺口。

逐项条件使用主台账 U01-K01—K09，按其方法和责任核验。退出要求九项及来源必需要求有效满足，范围取舍已有确认。失败回归对应 K 项，通过后复核 U02 前置。

### U02 桌面运行与数据基础

前置为 U01 有效交付。范围为桌面宿主、单服务、发行运行组件和数据保护。交付为源码锁文件、安装烟测包、生命周期和迁移恢复记录。

| 条件 | 核验方法及责任 |
|---|---|
| U02-K01 | 核验聊天复核固定模板生成记录、依赖锁及宿主差异 |
| U02-K02 | 实际测试无全局 Node 双击启动、第二实例及私有接口拒绝，保存进程和请求证据 |
| U02-K03 | 实际测试托盘、显式退出、桥停止及崩溃恢复，核验聊天复核 |
| U02-K04 | 使用数据副本验证迁移、失败恢复、原始历史与数据位置，核验聊天核对前后指纹 |

退出要求以上条件及 D02 适用验收通过。失败回归本卡，通过后复核 U03，可启动 U06 独立动效部分。

### U03 业务模型与方案发布

前置为 U02。范围为草稿发布和修复回归模型，先固定来源绑定接口。交付为模型/schema、迁移、业务界面和隔离规则证据。

| 条件 | 核验方法及责任 |
|---|---|
| U03-K01 | 固定样例验证原文出处、完整模型、集中补缺、差异确认及原子发布 |
| U03-K02 | 实测修复案例、轮次、中断、重试及重开，核对分母和回归位置 |
| U03-K03 | 实测需求覆盖、站内细化、新范围、认领接手及过期建议 |
| U03-K04 | 实测并发、响应丢失、磁盘失败及旧数据迁移，核验聊天复核版本和结果 |

退出要求适用规则和迁移通过，用户确认需求映射与回归呈现。失败回归相应条件，通过后复核 U04。

### U04 会话发现与真实接入

前置为 U03。范围为真实会话发现、绑定、九工具及事件适配。交付为接入实现、权限与幂等记录、覆盖能力表。

| 条件 | 核验方法及责任 |
|---|---|
| U04-K01 | 用户指定源范围，真实核对会话及绑定，测试同目录歧义、归档、半行、轮转和读取失败 |
| U04-K02 | 九工具逐项往返，核验聊天核对持久化结果、ID 和 revision |
| U04-K03 | 测试越权、伪造来源、重复、乱序、撤销及退出后的行为 |
| U04-K04 | 实测受支持事件、断线、新鲜度和漏报，记录覆盖未知或缺失的范围 |

退出要求真实接入及来源方案适用场景通过。失败回归对应条件，通过后复核 U05。

### U05 插件与核验闭环

前置为 U04。范围为单一 Skill `workbench-handoff`、安装接线、候选核验分权及跨聊天合流。交付为插件源码、实际调用记录、核验和修复回归证据。

| 条件 | 核验方法及责任 |
|---|---|
| U05-K01 | 真实安装并调用单一 Skill `workbench-handoff`，验证既有聊天续接及失败恢复 |
| U05-K02 | 测试普通候选无正式批准权限，固定验证器结果与交付版本可核对 |
| U05-K03 | 两工作树多聊天，经历两轮修复与换聊，核对轮次、接手、停滞决定及全局下一步 |
| U05-K04 | 测试一线阻塞、合流失败、证据失效，核验聊天检查全部依赖 |

退出要求用户能找到原目标与回归位置，权限及 LP04 适用业务场景有效通过。失败回归相应案例，通过后复核 U06 接线。

### U06 连续动效与一致视图

独立动效前置 U02，组合接线及关闭前置 U05。范围为 FX 动效与正式状态接线。交付为原生录像、区域/焦点测量、同版本快照及用户观感记录。

| 条件 | 核验方法及责任 |
|---|---|
| U06-K01 | 原生实测连续开合、中途反向、顶部锚点和透明区域输入，核验聊天复核测量，用户确认观感 |
| U06-K02 | 实测通知、编辑器持续输入、多屏/DPI/休眠恢复，逐项标明实际环境 |
| U06-K03 | 实测主/浮窗同 revision、重连乱序、通知去重与未读恢复 |
| U06-K04 | 用户查看修复支线、轮数、剩余差距及回归入口，核验聊天检查状态语义 |

退出要求 FX 必需项、D06 适用矩阵及用户确认齐全。失败回归具体条件，通过后复核 U07。

### U07 安装与恢复交付

前置为 U05、U06。范围为发行、升级、停用、卸载和恢复。交付为安装包与哈希、插件资源、版本清单及使用文档。

| 条件 | 核验方法及责任 |
|---|---|
| U07-K01 | 普通用户环境安装运行，核验聊天核对包内运行组件和实际版本 |
| U07-K02 | 测试中文空格路径、升级失败回退、授权撤销、停用与卸载 |
| U07-K03 | 停服务备份并恢复至新数据目录，核对方案、回执、核验、事务和游标 |
| U07-K04 | 逐项核对源码提交、包哈希、许可、操作示例及已知限制 |

退出要求安装与恢复适用矩阵通过，用户可按指引完成操作。失败回归具体条件，通过后复核 U08。

### U08 真实任务组合验收

前置为 U07。范围为安装后的真实多线任务和全部目标覆盖。交付为最终矩阵、证据索引、用户确认及结束回执。

| 条件 | 核验方法及责任 |
|---|---|
| U08-K01 | 逐项映射 D07、FX、组合、接入、P01—P16、G01—G08，核验聊天检查遗漏和证据适用性 |
| U08-K02 | 实际完成两线、反复失败、换聊天、停滞调整、回归、合流失败再修复的完整链路 |
| U08-K03 | 对照原始需求映射及全部未决项，核验聊天检查终点和整体结果 |
| U08-K04 | 用户确认全局位置与下一步清晰，实际桌面体验符合要求，生成最终交付记录 |

退出要求全部必需项有效通过、阻塞已处理且用户确认齐全。失败回归对应站点并重新评估依赖与证据，通过后按总纲记录项目结束。

## 4. 核验分工与证据目录

实际命令检查由执行聊天运行并保存输入、环境、退出码及产物。核验聊天对照指定提交和条件复核，必要时重新执行。范围、额外建议及验收标准变更由用户决定。原生动效与体验同时需要测量材料和用户确认。

主台账证据表保存索引，按 Uxx-Knn 关联。建议证据 ID 为 Uxx-Enn，同一产物可被多个条件引用。原始产物放在 app/test-results/manual-trial/ 对应执行 ID 目录，现有忽略规则覆盖该目录。记录绝对位置、哈希、环境及适用版本；提交的文档只保存脱敏摘要和索引。

派发前指定一个执行聊天和一个核验角色。若只能由同一聊天复查，记录实际身份与核验方式，需独立核验的条件继续等待指定核验者。

## 5. 备份与测试副本

文档备份由 Git 提交保存，本准备包提交后记录提交号。另已在 app/test-results/manual-trial/backups/ 创建本主题文档快照，校验信息见同目录 SHA256.txt。该位置受 Git 忽略规则覆盖，首次派发前再次备份最新台账。

业务数据备份在首次运行测试前执行。先确认实际 WORKBENCH_DATA_DIR 或桌面设置中的数据目录，停止该数据根的领域服务和写入者。将整个目录复制到独立带日期目录，包含事务日志和迁移快照，核对文件清单与哈希。将备份再复制为测试数据目录，使用 WORKBENCH_DATA_DIR 指向测试副本，启动后核对显示的数据根与固定样例。恢复演练也使用独立目录，逐项检查方案、历史回执、核验和关闭记录。

具体命令在确认真实数据根与服务入口后登记，业务数据备份状态为待执行。测试产生的状态与证据按实际版本登记到台账。文档快照和业务数据备份分别记录。
