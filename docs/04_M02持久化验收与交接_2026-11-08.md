## 实际交付与使用

项目原有创建、导入、保存入口继续可用。启动 `node app/server/launch.mjs`，选择项目，点击“管理任务与方案版本”：

1. 添加文件夹，填写名称及可选 Codex 项目标识。未绑定标识不会按名称自动匹配。
2. 添加或选择任务线，填写目标和终点条件，选择唯一文件夹。保存后已有任务不能静默迁移至其他文件夹。
3. 为同一任务添加多个聊天来源，分别记录聊天标识、仓库、工作树、分支、位置和时间。文件夹随选定任务关联，不另行猜测。
4. 添加方案版本及原文、日期、来源、章节、摘要、目标、验收和影响；选择初始及当前版本。已有版本原文不能覆盖，新修订追加版本。首次保存未绑定方案时，后续仍可首次绑定；已绑定的初始方案不能改写。
5. 管理站点所属任务、稳定编号、名称、范围、方案出处、验收、前置和合法后继。关系编辑中引用的是稳定标识，界面列出编号与标识映射。保存后任务及站点身份不可删除改写，防止换聊天重建任务。
6. 点击“保存任务关系”，重新读取或重启服务后再次打开核对。

新关系管理是后续 M03/M04 的数据输入；旧路线仍显示原手动报告，不代表新核验状态。新管理入口明确显示验收待核验，并可查看迁移时的原始报告。接入核验与地铁状态渲染分别属于 M03、M04；本次不冒充已完成这些能力。

## 存储与迁移边界

接口为 `GET/PUT /api/projects/:UUID/model`，项目身份由服务端已存在项目限定；独立 revision 乐观锁与串行写入拒绝旧版覆盖。每个项目关系保存在 `app/data/models/:UUID.json`（或指定 WORKBENCH_DATA_DIR 下）。数据及快照不进入 Git。

旧 `projects.json` 原样保留，读取新模型时先生成候选映射；首次保存关系时才持久化新模型，并以排他创建写入 `.json.legacy.json` 原始项目快照。该快照含原 ID、source、goal、revision、时间、站点字段和原始报告，迁移元数据带来源摘要。重复保存不重复创建实体或覆盖快照，快照与来源冲突时拒绝继续。

实现采用旁路新文件，避免替换旧主库；这将 M01 中“备份后切换”的物理步骤落实为旧库保留、新库另存和独立快照，不改变旧数据保护目标。需要整机恢复时仍应停服务并备份整个数据目录。未自动迁移真实运行目录，测试使用隔离临时目录。

关系更新通过临时文件与重命名发布，先保留上一版本 `.bak`。缺主文件但有备份时明确拒绝重建；损坏文件不清空；备份写入失败不更新当前版。恢复时停止服务，复制目录留证，检查并将有效备份恢复为原主文件名，再启动核对。首次发布失败可使用匹配的原快照重试，不能删除冲突快照后强行继续。

旧 done 只保留在 report 中，新站点 verification 固定 pending；写入 passed 被拒绝。原始 report 不可通过关系编辑篡改。关闭、回执和核验事件不在 M02 生成。
