## 实现范围

维护源沿用 `plugins/task-workbench/skills/workbench-handoff` 单一 Skill。新增确定性编号与引用处理、登记候选转换，以及会话/工作树固定映射、命名和宿主操作日志。源文档先由聊天按语义识别步骤与精确 UTF-16 范围，脚本不猜自然语言执行范围。已登记编号及 stepId 复用，新增插入使用锚点后缀，保留全部原身份、显式顺序、依赖与验收；并发来源变化拒绝写回。

会话按固定 ID 区分同名，映射包含方案、步骤集合、宿主项目、聊天、目录、分支与工作树序号。宿主操作使用稳定 operationId，成功结果幂等复用，失败及部分成功保留目标 ID，未知创建先查询原操作。实际 Git 根和分支分别核对。当前聊天已实际移动到既有宿主项目 `1d6d4cad-e93e-42db-80f3-e59b3fa6e61d`；幂等改名成功。宿主没有暴露普通项目创建、项目改名和聊天跳转工具，分别记录 unsupported，不以侧栏分区或文档打开替代。新聊天创建仅在用户明确授权后执行。

领域绑定支持受控显式接手，在一个事务内确认新责任、撤销旧责任、保存历史并转移原 executionId。迟到旧事件拒绝实时更新，持久保存待核对记录；原已提交事件仍可原键回放。补充事项的规划确认和必要事项取消由原生确认入口签发精确内容凭据，不能通过普通插件令牌自签。关联方案完成只解除对应阻塞，保留其他来源，来源自身仍须验收；旧 repairId 保留。

## 契约增量

共同契约 `light-1.0` 保持既有必填字段和工具名；本次为可选字段增量，旧请求继续通过。

| 位置 | 增量 | 约束 |
|---|---|---|
| bind | 可选 takeover.fromBindingId、expectedBindingRevision、executionIds | propose/confirm 同一意图，完整旧责任范围及全部未结束执行，可信目录分支确认，撤销不能附带接手 |
| supplementWrite | 可选 confirmationGrant、cancellationHandoff | 规划确认与必要事项取消由原生私有入口签发，内容变化失效，必要取消明确承接 |
| query/update | 历史查询可返回 state=pendingReview | 表示迟到历史待核对，既非实时提交也非自动可重放 |
| 私有入口 | POST /api/light-access/confirm-supplement | 原生主窗口路由许可，普通插件凭据拒绝，用户核对内容后签发短期限范围凭据 |

bindingIntents、continuations 和 lateReceipts 保存在既有持久聚合 metadata；原快照身份和历史事件结构保留。绑定/执行实时状态、验收和同步状态分别维护。确认与拒绝条件覆盖错误目录分支、责任重叠、不完整接手、内容偷换、凭据不足、旧版本与原键回放。
