# 登记字段校验与错误反馈修复

日期：2026-11-13

状态：真实失败请求已复现，源码回归、本机安装及实际安装桥复验通过

读取“执行方案01三步测试”聊天最新一轮的真实登记请求，发现 13 项 schema 错误：两处 SHA256 使用大写、endConditions 的元素为字符串、三个步骤的 acceptance 使用中文结果而非枚举、路线缺少六个必要字段，且 context 为字符串。服务严格拒绝是正确行为，但原回执没有字段位置，执行会话未能修正后接续。

本次保留严格契约，将真实请求保存为回归夹具；MCP 桥发送前检查完整请求，返回最多 40 条 validationErrors，包含字段路径、约束和消息，不回显请求值。HTTP 所有者也保留同类错误数据。增加自包含 runtime/validate.mjs 离线校验入口，并在 Skill 中要求用 registrationSnapshot 生成候选，提交前校验，收到明确参数拒绝后修正并继续已授权流程。

完整 npm test 通过：160 项服务/MCP、6 项领域、10 项 Skill，共 176 项。原失败请求复现 13 处错误，脚本生成的同一三步骤候选校验通过；未放宽验收、身份或授权要求。用户的这次方案仍未执行，本次不替执行聊天登记或运行它。

插件 0.1.15 已通过原生安装流程更新，独立 Skill 同步；源码提交 cf4b335。源码、独立 Skill、插件缓存及发布清单指纹一致，releaseReady=true，核验结果在 app/test-results/registration-validation-20261113/installation.json。

任务岛独立服务通过现有 stop/start 排空重启。实际安装桥再次运行普通目录完整登记、绑定、三个步骤及结束集成，2 项通过。安装后的自包含 runtime/validate.mjs 对原失败夹具准确报告 13 项错误。未代替用户在测试聊天中执行方案。
