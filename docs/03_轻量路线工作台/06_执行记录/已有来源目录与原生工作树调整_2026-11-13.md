## 本次行为

按用户“新项目选择已有同源文件夹，分支独立工作树”的修正，新线从真实 `sourceHostProjectId` 生成。默认复用该宿主项目，不调用项目创建或打开目录；需要独立侧栏归类时，显式提供 `separateProject:true` 和 label，新归类仍选择相同来源目录，按名称、host、路径回读。没有默认 Git 克隆行为，不再把执行工作树追加为项目来源。

来源目录、来源项目、新侧栏归类与实际执行工作树分别记录。新分支执行根在宿主创建前为 null。`create_thread` 使用已授权的原生 worktree 环境和明确的起点 ref；实际起点不存在或变化时停止，不在来源目录自动创建或切换分支。同源多线允许规划，实际同一执行根及同一开发线并发仍禁止。

原生创建回读后核验真实线程和项目归属、同一 Git 公共目录、不同执行根、起始提交和实际分支状态。原生 detached HEAD 使用 `branch:null,head:<真实提交>`，与无 Git 的 `branch:null,head:null` 分开。服务确认时核验真实起始提交，执行后允许同一 detached 工作树正常提交并沿用执行身份。

管理式工作树通常关联单个聊天。后继另建聊天时不能声称它复用前一聊天的执行目录；需在上一执行验收后明确后继 ref/提交，再规划和创建。没有新增“任意聊天绑定任意已有工作树”的虚假能力。

## 信任确认

来源目录复用可以避免默认引入多份克隆来源，但不能据此承诺新工作树一定不弹信任框。官方 [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees) 说明默认可能 detached、工作树与聊天关联；[审批与安全](https://learn.chatgpt.com/docs/agent-approvals-security) 说明实际权限与信任取决于环境。本轮没有在真实桌面新建执行聊天来验证是否免弹窗。

实际上下文 accessState=ready 才放行；waitingForTrust/denied/unknown 保留同一创建和聊天并停止实施。没有 threadId、只有 clientThreadId 时也可以用 workspace-wait 保存真实等待证据；这个入口不能设置 ready 或批准权限。确认后回读原结果并重验，不重复新建、不代点、不写信任配置。
