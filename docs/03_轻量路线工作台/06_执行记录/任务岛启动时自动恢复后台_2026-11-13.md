# 任务岛启动时自动恢复后台

日期：2026-11-13

状态：已实现并更新运行版

电脑重启后任务岛界面自启动，独立 Node 后台没有启动，旧发现记录仍指向已失效端口，导致连接失败。现在任务岛原生启动流程自动调用随应用打包的 `node.exe` 和 `app/desktop/service.mjs start`。已有健康后台直接复用；后台不存在时创建新服务并更新发现记录。界面轮询及 MCP 继续通过原有发现机制连接，保留授权与方案，不要求重新接入。

运行资源从可执行文件旁的 `workbench` 或安装资源目录定位。构建阶段由 `prepare:runtime` 准备，Tauri 资源配置随安装包携带；最终用户无需 Node 安装或开发目录。不要只移动单个 exe 而遗漏同目录资源。启动诊断写入数据目录的 `service-startup.json`，不记录令牌。原生输入调试夹具不启动正式服务。

实机验收运行 `app/tests/island-service-bootstrap.mjs`，没有手动启动后台：

1. 正常停止后台后启动任务岛，后台自动启动，读回 5 个方案。
2. 结束该后台进程并保留旧发现记录，再启动任务岛，自动恢复新后台及新服务身份，读回同样 5 个方案。

证据：`app/test-results/continuous-button/bootstrap-acceptance.json`，`passed=true`。这是应用与进程层面的冷启动/异常退出恢复验收，没有实际重启 Windows。新版界面和自带 Node 后台已保持运行。

前端 lint/build、Rust clippy、38 项 Rust 库测试及正式运行版构建通过。一次并行 HTTP 测试未结束，停止该次测试后串行重跑 38 项全通过。修改位于外壳仓库 `src-tauri/src/service_bootstrap.rs`、原生 setup、资源构建脚本与 Tauri 资源配置。
