# 多应用连接与顶部应用按钮

日期：2026-11-12

状态：实现与本地验证完成，交付状态见下方

## 实际需求和实现

按用户截图复用原项目应用胶囊按钮样式及 Codex、Claude 图标，放到展开面板上方，移除原“任务岛”文字。保留原设置、固定及显示大小按钮的位置偏好。提供全部、Codex、Claude Code、dsh、WorkBuddy、未分配六个筛选按钮。按真实服务绑定主体筛选整个任务组；跨应用协作任务可同时出现在多个应用下，不截断任务分支。未知历史不猜测归属，保留在未分配和全部中。

连接设置改成四个应用独立管理。Codex 沿用原根配置，其他应用分别使用 connections/<appId> 目录。每个应用独立授权、撤销、心跳和客户端会话；相同应用可有多个同时连接的聊天。STDIO 使用 WORKBENCH_LIGHT_APP 指定应用，服务核对应用与授权身份一致，不能按其他应用身份续期。35 秒心跳过期，关闭单个应用不影响其他应用。设置页导出不含令牌的本地 MCP 配置，公共运行入口位于用户目录 task-workbench-light/runtime/light.mjs。

绑定主体保存在服务元数据，面板只取得固定应用标识和连接状态，不取得令牌或主体凭据。禁止其他应用确认或覆盖已归属提案、已确认绑定；接手通过原有范围及版本核验流程。项目验收与方案发布规则保持原有语义。正式 envelope 契约增加可选 agentApps/bindingApps，light-1.0 业务快照结构不变，canonical 和外壳副本同步。
