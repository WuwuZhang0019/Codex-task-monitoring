## 最小安全干净构建方案

1. 固定最终两仓库提交后，在`app/test-results/island-F/`下新建独立本地clone（`git clone --no-hardlinks --no-checkout`后`checkout --detach <commit>`），不用现有Fork工作区target，不改当前安装版，不运行产品安装程序。若用纯git archive导出，应称源码导出构建，不冒称git checkout。
2. 在Fork clone执行`bun install --frozen-lockfile`，`bun run lint`、`bun run build`、`bun test`；在src-tauri执行`cargo clippy --locked -- -D warnings`、`cargo test --locked --lib`。已记录工具链为Bun1.4.4/Rust1.98，仓库仅Cargo.toml的rust-version=1.98，没有rust-toolchain.toml，需记录实际`bun --version`、`rustc -Vv`、`cargo -V`。
3. 构建NSIS：根目录`bun run tauri build --debug --bundles nsis --config src-tauri/tauri.nosign.conf.json`与E debug类型一致；若选择release则记录为新构建类型，不能沿用旧debug的二进制指纹。使用clone内target（或显式独立CARGO_TARGET_DIR），禁止覆盖原Fork target验收产物。
4. 业务clone在app执行`npm ci`、`npm run build`，`npm run desktop:resources`生成独立服务资源；该脚本会下载固定Node25.5.0并核对SHASUMS256，生成Node许可证、服务及MCP第三方许可、manifest。必须保留锁文件、源提交、实际命令与完整日志。单独MCP发行可执行`node mcp/package-probe.mjs <absolute-output> --require-clean`，输出带release-manifest和源码提交。
5. 业务资源prepare脚本包含删除**生成目的目录**行为，使用干净clone及先核对绝对输出根，再运行；不要从正在运行的正式服务目录执行。既有下载cache可复制到clone的ignored test-results/runtime-download以减少网络，但不得复制owner/token/data目录。
6. 固定源码包建议从各自提交`git archive`打包，附独立manifest描述两个提交、协议island-workbench/1、快照light-1.0及二进制SHA256。来源包只含受跟踪必要源码/许可证/锁文件/配置/脚本，不把node_modules、target、安装配置、service数据或密钥夹带。
