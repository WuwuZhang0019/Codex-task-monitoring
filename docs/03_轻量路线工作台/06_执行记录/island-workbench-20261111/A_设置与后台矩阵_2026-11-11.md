## 原版基线隔离要求与已知副作用

1. 使用外部临时 Tauri config 覆盖独立 identifier，并核实运行时实际 app_config_dir/app_data_dir，避免同用户原版共享配置、插件、shelf或clipboard。clipboard start 在enabled检查前删除自身临时图像目录，不能先用原版目录启动再补隔离。
2. 使用debug app:dev/二进制；updater.rs:23与tray.rs:208对debug直接返回，避免上游自动安装和首启自启动。不要点“检查/安装更新”、通知Enable、Claude安装/卸载Hook或任何账户连接。
3. 在子进程环境把 USERPROFILE、CLAUDE_CONFIG_DIR、CODEX_HOME、APPDATA、LOCALAPPDATA、GH_CONFIG_DIR 指向本次独立目录；保留实际Cargo/Rust工具链路径。不得修改宿主HOME/CODEX_HOME等系统变量。CLAUDE_CONFIG_DIR只覆盖 integration/transcripts；usage.rs:136直接用USERPROFILE/HOME/.claude/.credentials.json，须同时隔离用户路径。
4. activities api使用DYNAMIC_ISLAND_PORT/WINDOWS_ISLAND_PORT（默认5199）；Claude hooks端口47823是常量，冲突需记录，不改变原版常驻服务。
5. 即使独立identifier和目录，Windows Credential Manager仍是当前账户共享：music/spotify.rs:87—89无条件publish，:280—287读取CLIENT_TARGET和TOKEN_TARGET，不受module.music.enabled控制。settings不能完全避免该只读状态探测；完全零凭据访问须独立Windows账户或修改测试版本，本轮不应伪称完全隔离。不得输出凭据、点击连接或写入Credential Manager。
6. 可预置module.github.enabled=false、module.clock.enabled=false避免其round凭据/网络读取；module.clipboard/monitor/notifications.enabled=false减少采集，但不能使Provider线程不存在，也不能阻止clipboard start清理自身目录。音乐SMTC、Claude和Antigravity也不完全受模块开关控制。
7. Claude integration.rs:128 install/:181 uninstall只从显式provider action到达，启动仅integration::status只读，不会自动安装Hook。安装动作会先写时间戳备份，仍不应对用户原始settings运行。原版数据和Claude Hook全部保留。

以上是A基线条件说明，实际进程环境、目录、日志、动画录像与结果需由根代理证据索引关联，不能仅依据本静态矩阵宣布原生验收通过。
