## 问题与修改

多项目方案已准备目标目录，但协调规则只检查 `create_thread` 对已有项目的要求，没有项目创建接口就直接让用户逐目录添加。工作台项目与 Codex 侧栏项目是不同身份，普通登记不应引入这个前提；真正多项目归属需要单独准备宿主项目。

插件升级为 0.1.18，新增 `projects`、`stage-project`、`verify-project`。准备时核验实际 Git 工作树与分支，按宿主和路径匹配已有项目；创建工具实际可用时优先走原生工具，否则检查电脑技能允许的界面路径。界面路径只有可操作且被规则允许才能返回添加动作。所有路径受限后才汇总最少人工动作及具体原因。

添加前使用既有操作日志保存稳定意图；掉响应、界面与接口之间切换均不重复添加。添加后使用最新 `list_projects` 回读匹配宿主、目录和固定 ID，成功后再按已有 `map`、聊天上下文核验、服务绑定及开始许可继续。未修改宿主工具接口或业务步骤状态。
