# 连续执行按钮与阶段会话调度

日期：2026-11-13

状态：已实现并更新本机运行版

## 使用方式

方案登记后，在任务列表中点击路线右侧、归档图标左侧的“连续执行”。按钮采用 [Uiverse warm-turtle-37](https://uiverse.io/nazar-gavrylyk/warm-turtle-37) 的滑动圆球样式，缩短为 102 × 28 像素，开启时为紫色，关闭时为灰色。

服务按照方案依赖选择尚未完成的必要主阶段，每个阶段创建独立 Codex 聊天。一个阶段中的子步骤由该阶段聊天执行，所有必要子步骤验收通过后才接续。已完成阶段会跳过；开启时如果已有阶段正在执行，则观察原有聊天与工作台结果，不重复派发。

关闭开关只暂停后续接续，当前阶段继续执行至结束。再次开启时复用当前未完成聊天或进入下一未完成阶段。失败、等待人工决定、来源变化或验收未通过时停下并显示原因。服务重启后保持暂停，用户点击后核验恢复。整个方案必须满足步骤与最终验收条件才能结束。

此功能使用用户已安装并登录的 Codex，通过公开 app-server 的 thread/start、thread/name/set、thread/resume、turn/start 及 turn/completed 创建与跟踪真实聊天。服务负责确定性调度，不额外创建 AI 总控聊天。聊天在已登记路线的目录中运行，沿用已连接 Codex 的权限；没有可用连接时不派发。不依赖开发者机器的项目目录，不修改 Codex 私有数据库。

本次交付是单个已登记方案的阶段连续执行。多分支项目文件夹初始化、跨项目并行运行和 Git 合并自动化不属于本次已验证范围。

## 实现位置

- 服务：`app/server/light-continuous.mjs`、`app/server/codex-session-client.mjs`。
- 控制：仅所有者认证可调用 `POST /api/light-continuous/change`；WebView 通过固定原生命令提交方案身份、动作和版本，不携带所有者令牌。
- 持久化：聚合内的 `lightContinuous` 保存运行身份、当前聊天和执行身份、历史及暂停原因。掉响应或未完整启动时保留原身份，不盲目新建聊天。
- 原生界面源：`G:/rust/windows-dynamic-island` 的 `ContinuousButton.tsx`、`continuous-button.css`、`continuous.ts`、`src-tauri/src/continuous.rs`。
- 发行资源已经通过 `desktop/prepare-resources.mjs` 重新生成。

## 关闭状态反馈修复

日期：2026-11-13

原界面把 `pausing` 与 `running` 一起显示为开启，导致用户关闭后仍看到紫色按钮和暂停图标。现在只有 `running` 显示开启；`pausing` 立即显示灰色关闭状态和左侧播放圆球，提示“连续执行已关闭，当前阶段完成后暂停”。本轮后续修复同时允许在等待暂停时重新开启，复用当前阶段，不重复派发。

浏览器回归已覆盖 `running → pausing → paused → running`，检查等待暂停时的实际灰色、`aria-checked=false` 和提示。六项浏览器检查、56 项前端测试、前端 lint/build、Rust clippy 和 37 项库测试通过。本次更新仅重启任务岛界面，正式后台服务和阶段会话继续运行。

## 反复开关与原生输入补充验收

日期：2026-11-13

用户反馈上次修复仍不能操作。进一步修复以下问题：

- 去除 `pausing` 禁用，服务允许 `pausing → running` 取消等待暂停，继续复用当前阶段。
- 关闭属于接续控制，不再因模型同时更新业务版本而被拒绝；仍要求真实所有者、确认、有效方案及合法版本字段，开启与恢复继续核对最新业务版本。
- 服务在事务内核对等待暂停状态，旧调度循环退出后核对最新运行意图，避免恢复请求已接受但调度未继续。
- 开关加上拖拽隔离，防止轻微移动鼠标时整个岛开始拖动并吞掉点击。已完成方案明确提示“方案已完成，连续执行已关闭”。

实点验收使用 `computer-use` 技能的原生鼠标输入。透明悬浮窗不被电脑接口列为可操作窗口，因此提供仅调试版可启用的 `ISLAND_NATIVE_TEST_WINDOW`，显示同一任务岛页面、同一按钮和真实 Tauri/HTTP 调用链，使用隔离数据与阶段夹具；正式发布版不启用该入口。阶段执行器为夹具，不将本轮输入验收重复表述为真实模型执行。

实际坐标点击及后台回读完成 `running → pausing → running → pausing → paused`；所有状态使用同一运行和同一阶段会话身份。释放阶段后 A 为 `completed`，B、C 仍为 `pending`，只存在一个责任绑定。证据保存在 `app/test-results/continuous-button/native-input-evidence.json`，`passed=true`。原生截图中开关显示灰色且仍可操作，提示与后台暂停状态一致。

新增三项领域回归检查，连续执行领域共 12 项通过；桌面身份隔离另有 1 项通过。浏览器测试包含按下时移动 10 像素的点击与暂停中重复开启/关闭。前端 56 项、Rust 37 项、两端 lint 和正式构建通过。正式服务与界面均需重启后使用本轮完整修复。
