## 实际行为

- 工具发现和空闲心跳不启动应用。实际工具调用发现后台不可用时，按原生登记的 `launcher.json` 拉起或唤醒任务岛，等待原连接恢复。已知活动执行的心跳也可自动恢复。安装登记只保存可执行文件、进程、数据根和时间，来源方案不能指定启动命令。
- 原生任务岛看护独立后台；后台被强杀后自动重启。应用单实例入口识别 `--workbench-recover`，唤醒服务而不打开设置窗口。多个插件调用使用启动锁合并，并复用现有所有者及数据目录租约。
- 活动执行、running 步骤或正在运行/排空的连续任务会阻止正常退出。状态无法核对时先保护并恢复连接。退出提醒是归属于任务岛的置顶模态提示，只有确认按钮；确认提示不会终止任务。结束或取消活动执行后允许退出。后台正常停止同样受事务内门禁保护，多次正常停止请求不能绕过。
- 写入前在连接配置旁的私有 `recovery-events/` 保存精确请求，文件名按令牌作用域哈希隔离，文件内容不保存令牌。响应丢失时先查询原事件，已提交则返回原结果。未核清的请求保持 UNKNOWN_RESULT；同事件内容变化会被拒绝，明确重试也先查询再使用原事件，不能换键重复写入。
- 连续执行重启后仅恢复此前明确 enabled 的运行意图，核对来源、目录、绑定和原回合，再附着原回合等待结果。验收通过后接续；不重新发送已知原回合。显式暂停保持暂停；旧版没有 enabled 意图、创建/投递结果未知、权限或绑定变化时保留检查点并报告原因。

固定 endpoint 的旧配置保持原连接方式；自动启动采用 dataDir 配置。首次未运行新版、缺少安装登记，或尚未完成首次连接授权时，明确报告缺项，不从猜测的开发路径启动。任务岛及后台一起被强杀后的恢复依赖仍存活的活动插件连接或下一次实际工具调用；本实现没有增加系统常驻守护程序。

## 复现入口

业务检查：在 `app/` 运行 `node --test --test-concurrency=2 server/*.test.mjs mcp/*.test.mjs`、`node --test desktop/*.test.mjs`、`npm run test:domain`、`npm run test:skill`。新 Windows 工作树应先运行业务构建生成匹配当前合同字节的 schema；本次把合同工作副本规范化为 LF，未纳入语义变更。

原生夹具：`node tests/island-recovery-native.mjs prepare` 生成独立数据和配置；仅在隔离测试版设置 `ISLAND_NATIVE_TEST_WINDOW=1`、`ISLAND_NATIVE_TEST_SERVICE=1`、`ISLAND_WORKBENCH_DATA_DIR`、`WORKBENCH_ISLAND_LAUNCHER` 及独立 APPDATA/LOCALAPPDATA。测试二进制旁放 `.portable`，避免自启注册；构建用 `TAURI_CONFIG` 覆盖独立 identifier 与 devUrl=null。夹具的 `record`、`crash-service`、`verify`、`crash-both`、`recover-both`、`cancel`、`stop` 命令只针对本次记录的隔离目录。窗口操作由电脑操作技能完成，夹具不模拟 UI。
