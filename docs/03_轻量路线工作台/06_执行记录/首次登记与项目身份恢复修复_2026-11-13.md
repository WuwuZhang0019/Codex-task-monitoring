# 首次登记与项目身份恢复修复

日期：2026-11-13

状态：源码、回归、本机安装及真实安装桥集成通过；用户新会话验收待执行

## 问题

用户在新目录重新执行方案 01 时，执行会话在尚无 projectId 的情况下请求读取，得到 INVALID_INPUT 后要求用户手工建立项目。0.1.13 解决了普通目录的 Git 限制，但首次发布仍需桌面私有 confirm-publication 接口；此前隔离集成测试使用该私有入口签发票据，没有覆盖新会话仅通过 MCP 首次登记的路径。

## 修复

自动连接已启用的应用通过 MCP register/revise 传 `confirmationGrant: null`，服务核验当前自动授权、来源与候选，并生成真实项目和方案身份。旧版限范围连接仍须原有内容确认票据。未开启或已撤销连接不能使用自动登记。

get_project 可使用真实 projectId 或已保存的本地 projectKey 恢复项目；首次尚无身份时先登记，不用空 ID、路径或 Codex 侧栏 ID 发起读取。首次登记、同键查询、重复请求及修订继续沿用既有幂等和版本校验，不添加另一套项目数据。

桥的读取参数错误恢复提示改为提供有效身份或先登记；其他参数错误提示校验 schema，不再统一误导为检查所有者及授权。Skill 入口、登记参考和工具描述补齐完整首次接入顺序。插件版本提升为 0.1.14。

## 验证

- `npm test` 共 174 项通过，`npm run build` 通过。
- 普通目录从没有服务项目 ID 开始，只使用 MCP 登记、按本地 key 恢复读取、原事件查询、幂等重放、自动修订、自动绑定、三个步骤执行和方案完成。管理入口只用于测试环境建立及撤销应用连接，不调用私有发布确认接口。
- 空身份读取返回明确参数恢复提示；未登记本地 key 返回 NOT_FOUND；错误来源拒绝；旧版限范围模式的空票据仍拒绝。
