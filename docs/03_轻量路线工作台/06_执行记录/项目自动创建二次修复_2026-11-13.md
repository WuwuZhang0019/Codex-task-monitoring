日期：2026-11-13

状态：公开项目创建与回读通过，宿主派发身份仍为 1/4；插件安装结果见下文

## 根因与修复

0.1.18 只在规划器中选择原生工具或电脑 UI，没有真正创建项目的实现。电脑规则禁止 ChatGPT UI 后，流程再次停在手动添加。该规则约束电脑界面操作，不能据此推断公开程序接口不可用。

本次生成并核对本机公开协议 schema，发现 experimental app-server 已提供 `project/list`、`project/create`、`project/read`。新增自包含 `host-project-client.mjs`，协商 `experimentalApi:true`，以稳定幂等键与精确 roots 创建/复用项目。客户端不启动模型、不发送聊天消息、不读取或修改私有数据库。超时与失联保留未知结果，不重复创建。

新增 `prepare-project` 实际执行创建及回读，再调用官方 `codex://new?path=...` 工作目录入口，路径由 URLSearchParams 编码，使用无 shell 的进程调用和固定 Windows 启动命令。该入口不发送提示词，也不替代原生聊天派发。接口明确不支持时可继续官方目录入口。只有宿主 `list_projects` 按 host/path 回读后，`verify-project` 才写入成功及 `hostProjectId`。

官方依据：[Commands 的 Chats 深链](https://learn.chatgpt.com/docs/reference/commands#chats)说明 `path` 可以指定本地工作目录；[Developer commands](https://learn.chatgpt.com/docs/developer-commands#codex-app)说明 Windows `codex app PATH` 只打印路径，不能当作自动添加。具体项目 CRUD 以本机生成 schema 与真实调用为证据，不能仅凭网页或 helper 的 describe 推断任意版本都支持。
