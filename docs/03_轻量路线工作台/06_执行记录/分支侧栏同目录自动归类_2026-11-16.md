# 分支侧栏同目录自动归类

日期：2026-11-16

状态：实现与原生创建完成；安装核验单独回记

## 规则与实现

用户明确要求：有分支的方案自动建立各分支的 Codex 侧栏会话文件夹，路径仍与主会话相同，不能要求用户逐个手建。侧栏项目与磁盘目录、Git 分支是不同身份。

插件版本提升至 0.1.22。source-targets 主线默认复用来源项目，分支默认 separateProject=true，名称为来源名加 lineId，也可显式 label；方案03使用 test-A（A/B）、test-C（C/D）、test-G（G/H），与原 test 同指向 G:/rust/test。显式 separateProject=false 保留用户要求只用原侧栏项目的能力。普通 local 模式支持非 Git 目录，真实工作树模式仍要求 Git 和单独授权；资源冲突和未知结果保护保留。

公开 project/create 只建立公开项目记录，实测不会自动产生对应的具名原生侧栏项目；路径深链也不足以完成具名归类。prepare-project 因此返回 sidebarFallback；新 stage-sidebar-project 命令核对精确创建意图、当前授权、最新宿主缺项和电脑能力，先持久化 UI 创建尝试，再交给 Agent 自动操作原生表单。未确认的尝试不重复提交，已有名称、路径和宿主匹配的项目直接回读并复用。

实测原生路径为“文件→新建项目→名称→添加源文件夹→选择主会话原目录→创建”。选择器与父窗口的截图需分别处理，每次输入后刷新状态，不能重用旧索引或固定坐标。创建后必须以真实 list_projects 的 hostProjectId 回读验收；公开 project.id 不当作宿主 ID。不修改 Codex 私有数据库、不创建新的磁盘目录、不初始化 Git。

SKILL.md、协调参考、安装行为核验脚本及方案03样例文档均同步新规则。本次未覆盖 G:/rust/test 中已登记的方案原文或改写其验收状态，避免把侧栏整理当作任务恢复或重新验收。
