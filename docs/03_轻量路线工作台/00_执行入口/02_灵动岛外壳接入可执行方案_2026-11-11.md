# 灵动岛外壳接入可执行方案

日期：2026-11-11

状态：A 基线与授权范围本地验收完成；B—F 待执行；本方案服务登记与同步尚未发生

## 1. 目标与决定

采用用户 Fork 的 Windows Dynamic Island 作为桌面 UI/UX 外壳，将现有轻量路线工作台作为独立业务服务接入。保留上游外壳的动画、窗口行为和设置体验，替换其业务内容为项目路线与任务状态。

用户明确：模块、插件、快捷键不要，其他保留；接受 GPL 发布，两部分尽量解耦。本方案按“移除三类产品功能及其运行入口”执行，不仅隐藏设置菜单。内部可保留必要的组件组织方式，但不向用户暴露模块系统。

本方案为独立后续路线，本地标识 `island-workbench-20261111`。阶段 A—F 仅在本方案内有效，不覆盖旧路线 A—G 的服务 ID、台账或完成记录。原始版本仅授权方案落盘；当前 A 执行按下列用户授权修订办理。

### 1.1 A 执行门禁授权修订

日期：2026-11-11

授权依据：用户确认“按你的建议执行，继续完成 A 阶段”，接受 A 由 Codex 执行、以方案、Git 和证据文件记录；保留现有业务服务和旧界面，D 阶段再处理独立启动与新外壳接线。

- 仅本方案 A 取消“必须取得工作台服务开始回执后才能实施”的前置。Codex 可按当前用户授权定位或克隆 Fork、准备锁定工具链、运行原始浏览器及原生基线并记录证据；工作台工具未暴露不再阻挡上述 A 工作。
- A 的实际执行、验收和 Git 记录独立保存。服务未登记、未绑定、未收到事件或未回读时，服务 planId、stepId、executionId、bindingId 和 revision 继续留空；不得把本地执行或提交记为服务 synced，也不得借用旧路线身份。
- 此修订不取消业务服务的写入授权、绑定、版本、幂等与证据校验。若 A 确需调用正式业务写入，仍使用实际服务工具和原有受控确认流程；工具不可用时保留待同步，不以直接改数据库替代。
- 现有业务服务及旧界面作为可复用后端和备用管理入口保留。独立服务宿主、新外壳与 MCP 共享实例、跨 WebView 授权接线的实现归 D；A 负责核实当前行为并给出差距，不提前实施 D。
- A-01、A-02、A-03 和全部既定出口保持不变。未执行的浏览器、原生或动画条件仍据实标待验；浏览器结果不能替代原生结果。
- 本次仅执行 A，A 出口通过后只报告交接状态，不自动执行 B。B—F 仍按顺序、各阶段出口及其届时授权推进；本修订不自动豁免后继阶段门禁。

## 4. 两仓库结构与责任

建议 Fork 放在独立目录 `G:\rust\windows-dynamic-island`（执行前检查是否已有可用 checkout），使用 `origin` 指向用户 Fork、`upstream` 指向原作者；新增分支使用 `codex/island-workbench-shell`。业务仓库继续承载服务；不把 Fork 嵌进业务仓库，不复制数据库。

```text
Fork：窗口/动画/常规/外观/行为/关于
  └─ 固定工作台视图 → WorkbenchClient 适配器
                         ↓ 版本化本机协议
现有仓库：服务/授权/快照/状态机/持久化/MCP/宿主操作
```

外壳只持有界面偏好、连接配置和短期快照；服务持有项目、路线、步骤、绑定、补充事项和事件。外壳不得直接导入服务实现、访问数据文件或把业务规则复制进 React。服务也不得依赖外壳组件或其动画状态。

优先复用现有单实例服务发现、令牌和生命周期管理；A 确认当前服务是否由旧桌面进程拥有。若关闭旧 UI 会停止服务，A 记录差距，由 D 提取可独立启动的服务宿主后再接入新 UI，保证 MCP 与新 UI 共享同一实例，不能启动两个写入同一数据目录的服务。

协议类型、样例和版本说明可单独共享，修改记录集中在业务仓库，Fork 适配器记录兼容版本和来源提交；采用契约测试防止漂移。

## 5. 接口和交互约定

### 5.1 协议

- 快照优先适配已有 `GET /api/light-panel`：保持项目/路线/步骤固定 ID、五状态、依赖、绑定、补充事项和服务 revision；新增字段先做兼容性评估。
- 首版沿用已有刷新策略，隐藏时降频，恢复可见时刷新；若已有事件机制则复用，不凭空引入第二套实时总线。
- 区分健康检查、快照成功时间、离线、未授权、过期数据和版本不兼容。错误不得渲染为“全部完成”或自动切换模拟数据。
- 面板偏好按已有 `/api/light-panel/preferences` 语义保存；外壳主题与窗口偏好存外壳配置，两者命名空间独立。
- 业务写入继续走原授权服务，保留 eventId、expectedRevision、绑定及证据要求。响应丢失显示结果未知，用原事件键查回；冲突重读，不自动覆盖。
- 本机端口不等于授权。跨 WebView 调用优先走受控原生适配，保留既有身份校验；若使用 HTTP，限定 loopback、Origin/请求校验与凭据范围，不放开任意跨域，不把令牌写入日志或 URL。
- 聊天/工作树跳转按服务能力显示；能力不可用时给出可复制标识或路径，沿用当前降级，不伪造“已打开”。禁止接收并执行任意 shell 字符串。

### 5.2 工作台展示

| 状态 | 内容与操作 |
|---|---|
| 收起 | 当前项目、运行/阻塞/待处理数量、简短阶段状态；内容过长截断，详情可访问 |
| 悬停 | 当前阶段、最近进展和待处理摘要；沿用外壳动画，不触发业务写入 |
| 展开 | 项目分组、横向路线、阶段状态与依赖、选中阶段详情、刷新与定位当前 |
| 固定 | 操作和滚动期间保持展开；退出固定后恢复原行为 |
| 状态事件 | 阻塞、需处理、完成按配置提示；去重、节流并尊重全屏避让，避免连续抢占 |
| 服务离线 | 显示最后同步时间及重连入口，旧快照明确标记过期，禁用依赖实时状态的写入 |

旧面板已有长路线、深分支、焦点、滚动位置、完成事件定位能力应逐项迁入。数据状态文字保持一致；色彩和尺寸适配灵动岛主题，颜色配图标及文字。点击阶段仅选择/查看，不能直接把阶段标记完成。

## 6. 执行阶段与出口

全部阶段初始为 pending，验收 pending，尚无服务 planId/stepId。严格顺序 A → B → C → D → E → F；各阶段出口通过再开始后继。

| 阶段 | 细分步骤 | 交付与出口 |
|---|---|---|
| A 基线与授权范围 | A-01 核对两仓库、指令、状态及远端；A-02 锁定上游/Fork 提交和许可证；A-03 跑浏览器及桌面基线、录制动画、清点全部设置和后台入口 | 两仓库版本清单、保留/移除矩阵、可复现启动命令；明确服务生命周期及接口授权方式；原始动画有可比较证据 |
| B 裁剪外壳 | B-01 移除模块及采集；B-02 移除插件/快捷键；B-03 保留四类设置并补固定工作台占位、迁移旧偏好 | 页面与深链接无残留、后台不启动被删功能、基本键盘访问有效；构建通过，保留设置逐项核验 |
| C 契约与模拟视图 | C-01 固定 WorkbenchClient 和版本；C-02 接入模拟快照；C-03 实现路线/详情/状态切换 | 多项目、长路线、深分支、空数据、离线、未知结果样例；模拟明确标识；外壳动画与 A 基线对照 |
| D 真实服务接线 | D-01 独立服务生命周期及连接；D-02 真实读取/偏好；D-03 受控操作与宿主降级 | 同一真实项目 MCP 上报→服务回读→新外壳显示一致；重连、过期版本、拒绝授权、未知结果恢复通过 |
| E 桌面与恢复验收 | E-01 DPI/多屏/全屏/焦点；E-02 重启/升级/退回；E-03 用户观感确认 | 安装版通过必要场景；125%/150% DPI；多屏无条件实测时明确待验，不能记通过；不因新壳损伤旧业务数据 |
| F 许可与发布交付 | F-01 来源及依赖审计；F-02 安装标识/更新源/源码包；F-03 发布说明与最终回执 | GPL 文本、原作者声明、修改日期、依赖许可及对应源码齐全；可从干净 checkout 构建；记录两个提交与协议版本；实际公开发布另按用户授权执行 |

每阶段记录日期、分支/HEAD、修改范围、命令与结果、证据路径、未决问题和下一步。A 按 1.1 的授权先本地执行及验收；后续登记时使用本方案独立身份，成功回读后才写 synced；不挪用旧方案已完成身份。

## 7. 检查与回归

业务仓库在 `app` 下按变更范围运行 `npm run build`、`npm test`、`npm run test:desktop` 及相关 HTTP/面板场景。新增适配器测试覆盖契约版本、重连、乱序 revision、错误响应和操作幂等，不重复制造业务状态机。

Fork 在 A 阶段读取 scripts 后固定 lint、类型检查和构建命令；基于上游文档可从 `bun install`、`bun run dev`、`bun run app:dev` 起步，构建使用实际锁文件和工具链。浏览器通过不替代原生验收。

必要验收：

1. 启动、冷重开、托盘显示/隐藏/退出、开机启动偏好、设置保存与恢复。
2. 四类保留设置清单全覆盖，主题两种形态、形变/渐变/内容过渡录屏对照；快速悬停进出无闪烁或误收起。
3. 模块/插件/快捷键菜单与深链接消失，全局热键无注册，旧配置不重新启用被删监听。
4. 展开/固定/详情输入期间焦点正确，透明区点击穿透，滚动与定位不互相覆盖；125%/150%及可用多屏条件分别记录。
5. 两个 UI 与 MCP 读取同一服务 revision；被拒绝、阻塞、待处理、取消及完成状态均真实呈现。
6. 服务停止、重启、超时、旧令牌、版本不兼容可识别；重新连接无重复事件及旧快照覆盖新状态。
7. 安装/升级不覆盖上游产品、不误用上游更新源；卸载外壳不删除业务数据、MCP 授权和历史记录。

## 8. 配置迁移与回退

外壳使用独立应用 ID、数据目录、托盘标识和更新配置；配置带版本号。迁移采用白名单导入常规/外观/行为偏好，明确忽略原模块、插件和热键启用项，先备份再写入。不得删除用户安装的原版灵动岛数据或擅自移除其已有 Claude Hook。

新旧外壳并存验收时只启用一个常驻浮窗，二者连接同一受控服务。新壳失败时退出新壳并恢复旧 UI；只恢复外壳配置，不用旧数据库覆盖服务中的新业务事件。若协议扩展失败，回退适配器和前端，服务保留向后兼容读取。
