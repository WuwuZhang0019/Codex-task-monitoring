# Codex 会话与工作树关联细化方案

日期：2026-11-10

本文按已确认需求拆分模块职责、接口和验收要求。02_需求与视觉基线中的原指导方案及 UI 设计作为需求来源，本文与其他六份细化方案共同组织后续开发。

## 目标与命名规则

文档沿用原步骤编号，会话按 A、B、C 组织，各自映射原方案的一组步骤。同一会话内完成该组细分任务。

总方案直接执行时文件夹名称为方案名。多工作树时每个工作树一个文件夹，名称为 `数字表情 方案名 · Git分支名`。文件夹序号在方案内稳定登记，执行顺序依据原方案依赖。

## 两种组织示例

```text
制作示例任务看板
├─ [A] 数据准备
├─ [B] 界面展示
└─ [C] 交互验证
```

```text
1️⃣ 制作示例任务看板 · codex/mock-data
├─ [A] 数据准备
└─ [C] 数据校验

2️⃣ 制作示例任务看板 · codex/mock-ui
├─ [B] 界面展示
└─ [D] 界面完善

3️⃣ 制作示例任务看板 · codex/mock-validation
├─ [E] 交互验证
└─ [F] 结果汇总
```

## 开发内容

1. 建立方案、原文步骤集合、会话组织编号、会话固定 ID、侧栏项目固定 ID、Git 分支与工作树目录的映射。
2. 核对宿主项目和会话操作能力及授权通道，分别验证列表、绑定、改名、移动、创建和跳转。
3. 按两种命名规则生成名称，已有绑定时复用。超过九个文件夹使用逐位数字表情。
4. 将每个会话分配到实际工作树目录，执行前检查目录与 Git 分支是否匹配，记录实际运行上下文。
5. 支持接续会话绑定原步骤范围及执行记录，名称变化依靠固定 ID 更新关联。
6. 为改名、移动、创建分别保存结果和重试状态。能力缺失时提供建议名称及人工绑定入口。
7. 将方案名称或 Git 分支变化同步到已确认绑定的文件夹，保持稳定序号与历史。

## 接口与依赖

由 Skill 提供分配意图，路线模块校验步骤归属，存储模块保存映射，MCP 传递绑定资料，宿主适配执行会话管理操作。

## 验收

分别验证单文件夹和多工作树案例、同名会话、重命名重试、错误目录、接续会话和跳转失败。记录宿主实际支持范围及人工处理项。

## 交付

关联模型、命名函数、宿主适配、绑定与失败提示入口及实际操作记录。
