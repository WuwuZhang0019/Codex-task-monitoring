# 路线与状态管理细化方案

日期：2026-11-10

状态：新路线模块细化方案，待实施

本文按已确认需求拆分模块职责、接口和验收要求。02_需求与视觉基线中的原指导方案及 UI 设计作为需求来源，本文与其他六份细化方案共同组织后续开发。

## 目标与编号边界

保存 Codex 提交的原方案步骤及依赖，计算可执行范围与完成状态。文档保持原编号，会话 A、B、C 与原文步骤通过固定 ID 映射。

## 开发内容

1. 建立项目、方案、步骤、路线、依赖、工作树分配、补充事项及执行批次模型。方案记录来源路径、版本和验收要求。
2. 导入校验重复 ID、编号作用域、缺失引用、依赖循环和步骤覆盖。整体校验成功后发布同一版本。
3. 保存原文显式顺序及跨路线前置。根据依赖生成可启动步骤，全部前置完成后允许启动。
4. 维护五种站点状态。完成需要相应验收结果，阻塞需原因及恢复条件，取消需原因和后续前置处理，返工保留完成历史。
5. 前置未满足时展示待执行及等待对象。执行过程中需要外部处理的问题登记已阻塞。
6. 聚合路线及方案进度，按必要步骤、验收要求和阻塞事项计算整体完成。结束一次执行时独立记录执行结果。
7. 登记计划外事项的来源、目标、确认状态和阻塞关系。形成补充方案后关联固定方案 ID，解除事项阻塞后重新核对来源步骤。
8. 修订保留差异、取消及替代关系。并发更新通过版本检查提交，返工影响后继时记录待复核说明或阻塞。

## 接口与依赖

向 UI 输出快照、可执行范围和等待原因，向 MCP 返回业务校验结果。所有更新交由存储层持久化，Skill 负责从原文整理输入。

## 验收

采用现有二十步骤样例及六条工作树，验证一、二可并行，两者完成后启动三，三完成后四、五可并行，两者完成后启动六，六满足验收后方案完成。增加循环依赖、缺失前置、取消前置及返工影响后继场景。

## 交付

业务模型、状态转换与依赖规则、快照接口及定向验证记录。
