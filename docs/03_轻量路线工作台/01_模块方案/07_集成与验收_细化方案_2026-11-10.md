# 集成与验收细化方案

日期：2026-11-10

状态：新路线模块细化方案，待实施

本文按已确认需求拆分模块职责、接口和验收要求。02_需求与视觉基线中的原指导方案及 UI 设计作为需求来源，本文与其他六份细化方案共同组织后续开发。

## 目标与前置

将 UI、MCP、路线规则、存储、会话关联和 Skill 接成可验证流程。进入正式实施前核对实际仓库、并行改动、现有能力及七模块接口，确定复用和补齐范围。

## 建议集成顺序

1. 冻结原文步骤与会话映射、状态、依赖、事件、版本及保存回执契约。
2. 路线规则和存储完成最小提交读取流程，UI 使用同结构模拟快照推进。
3. MCP 接入同一业务入口，验证真实聊天往返。
4. 会话工作树绑定与 Skill 对接，贯通方案登记、执行上报和接续。
5. UI 接入真实保存状态，在实际桌面验证窗口及交互。
6. 完成异常恢复、安装启动和最终验收，记录未通过项与恢复步骤。

## 验收矩阵

| 场景 | 通过条件 |
|---|---|
| 二十步骤导入 | 工具编号、旧新映射、内容、依赖及验收要求完整回读 |
| 会话组织 | A、B、C 会话映射正确，细分步骤在所属会话内执行 |
| 六工作树依赖 | 一、二并行后汇合到三，三后四、五并行，二者完成后启动六 |
| 开始与结束 | 每次执行各一个逻辑事件，重试保持幂等 |
| 中间状态 | 五种状态、原因、证据和时间在 UI 与回读中一致 |
| 重复和冲突 | 重复事件复用结果，过期版本拒绝覆盖 |
| 中断与恢复 | 重启保留已保存结果，漏报可补交，未知结果可查询 |
| 工作树归属 | 会话实际目录、Git 分支及文件夹映射一致 |
| 方案完成 | 六条路线的必要步骤及验收满足，阻塞事项已处理 |
| 多项目 UI | 长路线、深分支、折叠、滚动及状态更新可用 |
| 原生桌面 | 展开收起、缩放、焦点、置顶与提示符合设计 |
| 安装使用 | 新启动可连接、读取持久状态并完成真实上报 |

## 测试资料

使用 03_测试样例目录的二十步骤六工作树模拟文档作为固定输入，保留固定原始样例作为输入，在独立测试副本中规范化步骤编号，并保存旧新映射及来源版本。按工作量将原文步骤映射到会话组织编号，并记录映射表。模拟数据以独立测试项目保存，验收记录注明环境、版本、命令或操作、预期与实际结果。

## 交付与结束条件

交付可运行应用、MCP 接入配置、Skill、使用说明、备份恢复说明及验收索引。每项证据标明模拟、自动化或真实桌面来源。必需场景全部通过后记录整体完成，待处理事项明确责任和恢复条件。
