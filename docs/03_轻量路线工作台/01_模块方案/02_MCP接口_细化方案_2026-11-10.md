# MCP 接口细化方案

日期：2026-11-10

状态：新路线模块细化方案，待实施

本文按已确认需求拆分模块职责、接口和验收要求。02_需求与视觉基线中的原指导方案及 UI 设计作为需求来源，本文与其他六份细化方案共同组织后续开发。

## 目标与输入输出

Codex 提交结构化方案和执行事件，服务返回保存结果、事件标识与版本。提供按需读取，支持新会话接续及冲突恢复。

## 开发内容

1. 核对现有 `app/mcp`、工具发现、契约和实际服务能力，编制可复用接口与待补齐字段清单。
2. 定义方案登记或修订、状态读取、开始、步骤状态变化、阻塞、结束回执、补充事项及会话绑定的接口映射。优先映射既有工具。
3. 输入携带项目、方案、步骤、执行、会话的固定 ID，来源文档版本、原文步骤编号、事件 ID、预期版本和发生时间。会话组织编号单独保存。
4. 校验授权范围、实体归属、必填字段和数据规模，将业务更新交由路线模块处理。
5. 同一事件同内容重复提交返回原结果，同 ID 异内容拒绝。过期版本返回冲突及当前版本。
6. 完成持久提交后返回成功回执。超时和响应丢失保留未知结果，可使用原事件 ID 查询或重试。
7. 任务开始和结束各提交一个逻辑事件，中途在步骤切换及阻塞变化时补报。结束事件表达结果、证据和未决项。
8. 暴露实际能力、连接诊断与脱敏错误，统一 UI 与 MCP 的状态来源。

## 接口与依赖

依赖路线模块进行状态及依赖校验，依赖存储模块提供原子提交与事件查询。服务响应字段供 Skill 使用。工具数量及名称在实施前与现有契约核对后冻结。

## 验收

真实聊天完成发现、读取、开始、状态更新和结束往返。覆盖重复调用、并发冲突、错误归属、撤销授权、响应丢失与重试，D 核对真实调用与持久回读一致，F 再核对回读结果与真实面板一致。

## 交付

工具契约、服务适配、错误与回执定义、接入配置说明和真实调用证据。

## 新路线统一决定

更新日期：2026-11-10

当前阶段前置、旧交付复用及三类接口采用[新路线实施总纲](../00_执行入口/00_新路线实施总纲与接口决定_2026-11-10.md)。步骤状态使用 `workbench_update_step_status`，补充事项使用 `workbench_record_supplement`，会话与工作树绑定使用 `workbench_bind_context`，对应 schema 与实现待交付。UI 以[原始样式清单](../02_需求与视觉基线/原始UI样式保留清单_2026-11-10.md)为视觉对照，并采用最新展开结构和尺寸。


## 对应执行步骤与验收归属

更新日期：2026-11-10

A 固定契约；D 完成真实 MCP 往返；E 联验绑定与 Skill；F 核对面板一致性。

验收包含已提交事件回放先于版本检查、同键异内容拒绝、授权与归属校验，以及绑定撤销后的写入拒绝。三个统一接口名称采用总纲决定，现有工具适配须验证业务语义。

执行顺序、统一接口与必需出口采用总纲的“步骤与模块交付矩阵”。本文件中的开发列表为所属工具步骤的子项。
