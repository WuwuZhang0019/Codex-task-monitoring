## 应用与接入

Windows 应用名称为“任务航线工作台”，当前桌面版本 0.2.0。NSIS 安装包由仓库 `app` 目录运行 `npm run tauri build -- --debug` 生成到 `app/src-tauri/target/debug/bundle/nsis`；debug 包用于本次交付验收。发行资源包括独立 Node、服务、页面和 MCP 桥，普通运行不依赖系统 Node 或开发服务器。首次运行依赖 Windows WebView2，安装器按其配置处理。

默认桌面目录为 `%LOCALAPPDATA%\com.codextaskmonitor.workbench`，业务数据在其 `data` 子目录。以应用显示的实际目录为准。测试根仅在 debug 构建通过 `WORKBENCH_DESKTOP_TEST_ROOT` 指定，勿将隔离验收目录当作正式数据。

1. 启动应用，已有实例时复用实例。主窗口关闭可能隐藏到托盘，停止服务须使用“退出工作台”。服务停止标记存在时通过“恢复服务”显式启动。
2. 主窗口“Codex 接入 → 连接授权”填写项目关联键、真实聊天固定 ID、宿主 ID、工作树绝对路径，核对范围后授权保存。正式业务 ID 来自发布回执；只读 probe 的隔离身份不能用于业务。
3. 使用 `task-workbench:workbench-handoff`，提供方案路径及台账。先提取、规范编号和校验，再通过原生确认入口发布。方案内容确认与绑定确认分别执行。
4. 会话提案绑定步骤集合、目录及实际分支，原生确认入口核验 Git 后签发限范围凭据。确认绑定成功，再预留 executionId 并取得 running 回执，开始实施。新聊天不得借用其他聊天的写入身份。
5. 顶部面板悬停展开、移出自动收起；点击固定，Esc 分层退出。完成事件提示须点击或按 Enter 才定位，普通刷新保留阅读位置。聊天跳转能力缺失时显示固定 ID 供查找。
6. 完成步骤提交逐项验收和证据，回读核对状态。任务线和项目完成分别判断；聊天结束不等于项目完成。

## 备份与恢复

1. 使用“退出工作台”正常停止，确认进程与所有者退出。不要在写入期间复制正式数据，也不要让两个写入者共用一个目录。
2. 将完整 `data` 目录复制到独立备份位置，保留 `aggregate.json`、备份、迁移快照、事务文件及历史子目录。页面“导出项目”仅导出旧模型，不能替代全目录备份。
3. 在应用停止时，将备份恢复到新的空目录；保留原目录以便回退。确认 `aggregate.json` 的来源、完整性和版本，再由所有者正常启动并回读项目、方案、步骤、事件、绑定、版本及原事件幂等结果。
4. 同一机器的完整恢复可能包含有效授权。不要共享原始备份；跨机器、改变目录或新聊天后重新核对授权和绑定。路径声明不等于有效绑定。

目录迁移使用随应用携带的 Node 和 `runtime/app/desktop/migrate.mjs`，传入独立的源目录及空目标目录。开发环境示例：

```powershell
node app/desktop/migrate.mjs "D:\backup\workbench-data" "D:\restore\workbench-data"
```

迁移核对源、暂存和目标指纹，保存备份及清单，拒绝已有目标数据和符号链接。源服务必须先停止，含提交标记的源目录须先由原所有者恢复。迁移中断后目标的 `.migration-pending.json` 会阻止启动；保留源、目标和备份，通过显式恢复回到空目标后再迁移：

```powershell
node app/desktop/migrate.mjs --recover "D:\restore\workbench-data"
```

不要自行删除事务提交标记或迁移标记来强行启动。`RECOVERY_REQUIRED` 表示需要重开恢复或核对备份；损坏文件须保留证据，不创建空库覆盖。

## 中断与失败处理

- 写入超时或响应丢失：保留 eventId 和原始请求，先查询原事件，必要时原键原内容重放；未知期间不宣布失败或生成第二次执行。
- 版本冲突：读取最新 revision，核对并行更新后决定新操作，不覆盖其他聊天提交。
- 授权拒绝：核对真实聊天、项目和目录范围，通过原生入口恢复；只读成功不证明写入授权。
- 前置失效或绑定撤销：停止实施，保存等待对象与解除条件，恢复时重新取得许可。
- 请求超过2MiB：预期返回413；若遇到 ECONNRESET，保留实际命令、并发环境及服务日志，原事件查询后再判断是否提交。
- 提交后应用异常退出：由原所有者启动恢复，回读版本、历史、幂等结果；未收到结束事件时保留最后状态和待确认，不猜测完成。

实际故障注入、六路线、安装和原生环境证据由 `../06_执行记录` 中 G 记录提供；未验收项不能依据本说明标为通过。
