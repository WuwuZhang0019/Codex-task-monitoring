## 交付与使用

主界面新增“核验监测与自动收敛”，按任务线展示站点和依赖，直接消费 M03 的有效证据与交接核验；每 5 秒读取，亦可手动刷新。原手动记录另有明确标识，站灯改为灰色，不冒充新版验收监测。

| 情况 | 新监测显示 |
|---|---|
| 未执行，前置或来源未齐 | 暗色＋等待依赖/待绑定，列出等待站点 |
| 前置及对应交接边通过，但没有实际开始记录 | 暗色＋可开始 |
| 正确聊天来源登记实际开始证据 | 绿色＋进行中，显示来源、时间及证据位置 |
| 报告完成但缺必要核验 | 暗色＋待核验，不因为旧 done/active 亮灯 |
| 本站有效验收通过 | 红色＋已完成；交接偏离另以文字说明 |
| 本站已验收，仍有前置未满足 | 本站红色＋等待前置，后继不解锁 |
| 证据或核验失效 | 当前待复核，不继续用失效证明解锁后继；保留关闭历史 |

点击站点可查看范围、判断理由、等待对象、实际聊天和开始证据。登记实际开始只写入来源记录，不发送指令或运行开发任务；前置未齐、来源错误、已完成或已处于执行中的站点不能再登记开始。同一执行标识重复登记不增加事件，同标识用于不同内容会拒绝。新完成回执或核验结果会结束此前绿色状态的适用性，不用过时开始记录覆盖后来的失败/待核验结果。

任务和项目分别显示原定目标、当前目标、实际交付、验收结果、是否符合最初预期、偏差与交接对象；可展开关闭时的证据快照和完整开始、关闭、待复核历史。

## 原始目标与保守迁移

任务管理新增 initialGoal（原始任务目标），按初始方案明确后保存，之后不可覆盖。旧模型此前没有独立保存这个字段，不能把当前目标猜作原始目标：缺少时明确显示待确认，不自动关闭该任务。界面无需逐次批准关闭，只需在方案基线管理时补齐确有来源的目标。

回执核验中的任务终点条件同时显示 `原始任务目标：<initialGoal>` 对照项，由操作者按 M03 的独立证据方法核验。该对照落实方案要求的“原目标→实际交付→验收→是否符合最初预期”，不是新增站点、可选优化或移动终点。保存原始目标后若影响已有核验，M03 会将有关记录保留为待复核，不伪造历史通过。原项目目标仍来自不可覆盖的初始方案，当前方案不遮盖原目标及验收。

旧项目仅查看监测时不提前固化尚未保存的关系模型，避免空项目随后导入路线却被旧空快照冻结。M02 已保存的关系、M03 历史日志及原数据继续保留；本次验证只使用隔离临时数据，没有迁移或修改用户真实运行目录。

## 自动关闭与存储

实现位于 `app/server/monitor.mjs`（规则版本 m04-v1）、`app/src/Monitor.tsx`，复用 `model-store.mjs` 的串行队列、revision、备份与原子发布。

- 任务关闭：原始目标已明确且有对应有效对照证据；全部必要站点及依赖有效通过；终点为 M03 的有效 E/F 交付判断，头尾范围明确，无交付阻塞。各任务独立计算，其他任务或集成未完成不会重新打开已交付任务。
- 项目关闭：所有必要任务满足各自条件，并有项目级、初始方案及原项目目标的有效验收；不能仅凭开发任务关闭推断项目结束。
- 模型或回执/核验写入时自动收敛；读取监测时也对已保存关系模型自动补齐收敛状态。关闭无需额外确认。相同证据与状态不重复增加关闭事件或 revision。
- lifecycle 中 starts、closures、events、receiptPositions 和 observed 均由服务端维护。普通模型 PUT 不能篡改历史，不能直接提交客户端“已关闭”状态。
- 每次关闭保留独立 ID、时间、规则版本、对象、目标、实际交付、验收引用、初始符合性、偏差、交接和证明摘要。证据失效后追加待复核事件，不删除关闭记录；复验通过可追加新的关闭记录。
- `GET /api/projects/:UUID/monitor` 返回有效监测、任务/项目及历史；自动收敛可能在必要时持久化新关闭/复核事件。`POST` 使用 revision、stationId、sourceId、executionId 和 evidence 登记实际开始；冲突返回 409，无效开始返回 400。

关闭后的“无下一步执行指令”输出属于 M05。本次不伪造指令生成能力；已关闭任务的开始登记已被禁止，后续责任按交接对象展示。
