0.1.25 对齐用户复制指令与默认提示：提供方案文档并调用技能即自动登记待执行路线，首次状态 pending；已有登记复用真实进度。无需额外接入口令，不默认开始执行或先审历史证据。任务岛 Skill 页同步使用相同提示。

0.1.24 明确固定顺序：提取路线、校验登记、回读路线、绑定及开始门禁、业务核验与实施。上岛前只读接入必要资料，不先开展恢复资格、账户核算或历史证据全量审查；历史进度待核验不阻止路线登记。默认调用提示同步采用此顺序。

0.1.23 将自动恢复/登记放在技能调用入口，执行、继续、核对、生成交接均不再要求用户额外说“接入”。无登记时自动生成并校验完整请求，通过 MCP 登记后回读方案、步骤与路线；已有身份复用，不重复建卡。新增 registration-request.mjs 生成稳定键及可恢复的精确请求。明确不写服务、仅解释技能或没有具体任务时不登记；登记不会自动授予派发聊天、真实供应商或开始后继步骤的权限。服务接入成功与原生任务岛显示分别核验。

0.1.22 对有分支的方案保留主项目，并给分支建立独立侧栏项目文件夹；这些项目都指向同一个来源目录。普通逻辑分支使用 local 环境，非 Git 目录也可核验和准备；只有用户明确指定独立工作树时才采用 managed-worktree。创建后以真实宿主项目 ID、名称和路径复核，移动已有会话只改变归类，不恢复任务执行。

0.1.20 的 `prepare-project` 实际调用公开 app-server `project/list`、`project/create`、`project/read`，使用稳定幂等键创建或复用精确目录项目，再通过官方 `codex://new?path=...` 入口让桌面采用该目录。该路径不使用电脑界面自动化，也不要求用户逐目录添加。公开协议返回的 `project.id` 与宿主 `list_projects` 的 `projectId` 是不同身份，必须按宿主和真实目录回读后，经 `verify-project` 才能保存 `hostProjectId` 并 `map`。公开协议成功或深链启动成功仍只记为待核验；超时失联不重复添加。Windows 的 `codex app PATH` 仅打印目录，不作为创建路径。

0.1.18 为多项目协调增加 `projects`、`stage-project` 和 `verify-project`：按真实宿主和目录复用项目，保存稳定意图并核验 ID。该版只提供缺项分流，缺少实际创建实现；0.1.20 补齐公开协议与官方入口。普通登记仍不要求新建侧栏项目，不绕过电脑工具对应用或权限操作的限制。

0.1.17 提供 `binding-request.mjs --context` 自动检查当前命令环境中的会话 ID、本地宿主及实际目录；缺少 service snapshot、事件键和会话身份分别报错。Skill 要求实际运行检查，不能只阅读脚本后判断缺身份，也不能无限继承历史未知结果。

0.1.16 增加 binding-request.mjs，用实际会话、目录与已登记 snapshot 生成完整绑定请求；绑定与状态工具向宿主展示明确字段，条件组合仍由服务端原始 schema 严格校验。所有写请求在提交前离线校验并保存事件键，拒绝空绑定及空事件查询。

0.1.15 增加 `runtime/validate.mjs` 离线完整请求校验器，MCP 桥在发送前返回具体错误字段路径，HTTP 所有者保留同类诊断。Skill 要求用结构化脚本生成候选，校验失败时修正后接续，避免一次 INVALID_INPUT 后停工。

0.1.14 补齐自动连接后的首次登记：MCP register/revise 使用 `confirmationGrant: null`，无需已有项目 ID 或桌面私有确认接口；登记响应生成真实项目与方案 ID。已有本地 projectKey 可用于恢复读取，缺 ID 时先登记，不要求用户在任务岛手工创建项目。旧版限范围授权仍保留内容确认门禁。

本版新增授权协调模式、分线映射、两段原生工具调用、可恢复派发日志及服务检查点。协调者复用既有绑定、executionId 和开始门禁，按真实依赖选择本批开发线。仅生成模式不创建或派发。当前宿主直接创建不支持任意已有工作树路径，不能把提示词换目录当作原生归属成功；具体流程见 [协调参考](skills/workbench-handoff/references/coordination.md)。

## 运行与授权

插件身份沿用 `task-workbench@task-workbench-u01-local`，MCP 连接键保留 `task-workbench-u01`。0.1.5 的实际入口为 `runtime/light.mjs`，连接领域所有者，0.1.26 支持按原生登记按需启动任务岛并恢复连接。桥通过所有者返回的工具清单提供路线读取、登记或修订、执行身份预留、步骤状态、补充事项、会话绑定、事件查询及方案验收能力。

领域所有者持有数据根租约。桥读取受控本机配置，所有者由任务岛入口启动并看护；断线恢复仍经原生入口，不另建数据根或绕过授权。配置文件由 `WORKBENCH_LIGHT_CONFIG` 指定，缺省为用户目录 `.codex/task-workbench-light/config.json`。常规配置包含 `dataDir` 和 `token`，`dataDir` 为所有者数据根的绝对路径。桥在每次请求前读取 `owner.json`，跟随端口及 generation 变化，并遵守 `stopped.json`。固定端点试跑也可采用互斥的 `endpoint` 和 `token` 配置，端点仅允许 `http://127.0.0.1:<port>` 根地址。令牌为独立于桌面会话的至少 64 个十六进制字符。凭据由所有者授权入口生成并受控保存，插件包只携带运行代码与 Skill。

认证和项目范围由所有者逐次校验。发布需要可信入口签发的内容确认，绑定确认需要目录、分支及限范围凭据核验。具体开放能力以服务回执中的 `supportedCapabilities` 为准。写请求超时或连接中断返回 `UNKNOWN_RESULT`，调用者保持原 `eventId` 查询提交结果，桥不自动重发写入。

0.1.5 在每次工具发现和请求前重新校验受控连接配置，使原生授权轮换后仍使用当前凭据；配置失效时失败关闭，不沿用旧令牌。新会话责任仍须重新受控绑定，配置轮换本身不表示接手成功。

## 打包

先安装 app 的锁定依赖，再在仓库中运行以下命令。脚本沿用历史文件名，构建对象已经切换为轻量桥。

```powershell
node 'G:\rust\Codex-task-monitoring\app\mcp\package-probe.mjs' 'G:\rust\Codex-task-monitoring\app\test-results\manual-trial\E-EX01\release' --require-clean
```

输出包括自包含运行脚本、第三方许可、插件清单、现有 Skill 及其参考文件、构建元数据和原 marketplace 身份。打包产物保存在独立发布目录，安装结果和独立 Skill 更新分别记录。

提交相关源码后使用 `--require-clean` 发布。`release-manifest.json` 记录源码提交、版本、脏文件状态与发布文件 SHA256；入口、全部 references 及 scripts 均纳入。无此参数的开发包仍记录真实脏状态，不能当成明确源码发布证据。同版本内容变化须提升版本，使用宿主安装流程更新，禁止手改插件缓存。独立安装的同名 Skill 与插件来源分别核对，实际本次加载路径由新聊天报告。

所有者、独立令牌及本机配置就绪后，沿用已验证的本地发布流程。

```powershell
codex plugin marketplace add 'G:\rust\Codex-task-monitoring\app\test-results\manual-trial\E-EX01\release' --json
codex plugin add 'task-workbench@task-workbench-u01-local' --json
```

安装后分别核对版本缓存、清单、运行脚本和 Skill 文件指纹，保存真实工具发现、无害读取及业务写入回读证据。当前 CLI 帮助没有插件热重载命令，现有聊天刷新能力需实际验证，新聊天的发现结果单独记录。文件一致、Skill 可见及实际流程通过分别验收，Skill 安装和新会话流程按 E 阶段推进。

历史 U01 只读探测源码与证据继续保存在 `app/mcp/probe*.mjs` 及历史目录，0.1.3 已安装缓存按原安装结果保留。真实面板接线与原生观感验收按 F 阶段执行。

## 自动启动与恢复（0.1.26）

日期：2026-11-16

新版任务岛启动时将当前可执行文件、进程及数据根登记到受控的 `~/.codex/task-workbench-light/launcher.json`。插件仅在实际调用或已知活动任务断线时按此登记启动，使用 `--workbench-recover` 唤醒单实例并恢复服务；仅工具发现不启动应用。已有服务及原连接授权被复用，缺少安装登记或首次授权时明确返回缺项。固定 endpoint 的旧配置仍按原连接方式工作，自动启动使用 dataDir 配置。

写请求在连接配置旁的私有 `recovery-events/` 保存原文（不保存令牌），用原事件核对响应丢失；已有提交不重复写入。用户暂停意图保留，连续执行重启后核对原会话回合并自动续接，未知投递不重复派发。活动执行阻止正常退出；任务管理器强杀后的恢复依赖仍存活的插件连接，或下次实际工作台调用。
