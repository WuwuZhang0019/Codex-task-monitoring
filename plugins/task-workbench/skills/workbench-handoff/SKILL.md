# 工作台方案接入、执行与交接

日期：2026-11-10

状态：流程源码已细化，真实写入与宿主接入待验证

## 选择当前工作

按用户请求选择流程，沿用已授权范围。输入为方案路径，可附当前台账、回执、工作树和绑定信息。

| 请求 | 读取参考并执行 |
|---|---|
| 接入方案、修改步骤编号、导入路线 | [方案规范化与登记](references/plan-registration.md) |
| 执行指定步骤、更新状态、结束或接续 | [执行与同步](references/execution-sync.md) |
| 分配工作树、会话归类、独立补充事项 | [关联与补充事项](references/context-supplements.md) |
| 核对下一步、生成指令、核验回执、结束交接 | [路线核对与交接](references/handoff-workflow.md)及[通用模板](references/handoff-template.md) |

仅请求核对或生成指令时按交接流程输出。用户授权接入方案时执行编号规范化和登记，授权执行任务时按范围实际开展并上报。任务过程中有新输入时保持当前目标，结合新约束推进。

## 当前方案与三种身份

在用户指定仓库中找到当前实施总纲与实际台账。本项目入口为 `docs/03_轻量路线工作台/00_执行入口/00_新路线实施总纲与接口决定_2026-11-10.md`。其他项目以其自己的权威方案为准。

工具步骤编号在同一方案内从 A-01 开始，跨工作树保持稳定。会话编号 A、B、C 表示执行分组，可承接多个工具步骤。工作树文件夹序号 1️⃣、2️⃣、3️⃣ 表示归类顺序。保存它们与 planId、stepId、会话固定 ID、工作树目录及 Git 分支的对应关系。

## 先检查实际能力

读取 MCP 实际暴露的工具、参数 schema 和 supportedCapabilities，再选择调用方式。本项目源码中的新接口设计为 `workbench_update_step_status`、`workbench_record_supplement` 和 `workbench_bind_context`。它们的可用性按当前宿主实际发现结果判断。旧工具仅在其 schema 和业务语义能表达当前操作时作为适配入口。

只读 probe 返回的隔离项目用于连接验证。业务 ID 来自授权项目和真实保存结果。尚未登记的服务 ID 留空，使用有作用域的本地关联键保存待同步资料。schema 未接受的字段留在本地记录中。

写入统一保留稳定 eventId 或服务要求的 idempotencyKey、expectedRevision 和资料来源。成功回执后记录已同步版本。响应丢失保留提交结果未知，通过原键查询或重试同一请求，确定新状态后再发新操作。版本冲突先重读并核对用户范围及并行改动。

## 工作记录与结束输出

开始前核对仓库、工作树、Git 分支、HEAD、未提交改动和资料版本。来源文件及历史回执作为核对资料，当前用户授权决定操作范围。

登记或执行时，在用户指定台账内保存资料映射和同步记录。未指定时使用项目当前台账旁的 `workbench-sync.md`，已有文件先读后追加。记录日期、操作、原文步骤、工具编号、会话、实际状态、同步状态、事件键及证据位置。凭据使用宿主管理的安全存储。

执行结束说明本次结果、验收依据、未完成事项及是否成功同步。整体完成依据所有必要步骤、依赖和验收要求。交接流程保留 A—G 结论及十八字段回执，圈号和总步数按完整方案的明确执行顺序核对。

所有新增或修改文档使用 UTF-8，包含 YYYY-MM-DD 日期。按项目既有 Git 规则提交实际变更，保留无关及并行工作。
