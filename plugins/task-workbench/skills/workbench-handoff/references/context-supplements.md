# 会话工作树关联与补充事项

日期：2026-11-10

状态：Skill 操作规则

## 会话组织

总方案直接执行时文件夹使用方案名，内部会话采用 `[A] 数据准备`、`[B] 界面展示`。每个会话对应原方案的一组工具步骤，组内步骤在该会话连续执行。

多工作树时文件夹采用 `1️⃣ 方案名 · codex/实际分支`，每个工作树一份文件夹，会话在同一方案内统一分配 A、B、C。一个工作树可负责 A、C，另一个负责 B、D，执行依赖仍由方案决定。序号稳定登记，超过九个使用逐位数字表情。会话主题与实际任务一致。

使用实际工作区工具查询目录与 Git 分支，工作树创建遵循用户已有授权。使用结构化 `workbench_bind_context` 的 propose 提交步骤集合、会话组织编号、外部身份、目录及分支。保存 bindingId、bindingRevision、待确认问题和拟定名称。

confirm 使用已认证 UI 或其签发的限范围确认凭据。来源声明和已确认身份分别保存。执行引用有效绑定版本，撤销后拒绝新写入。重分配保存接手关系与旧责任执行，一步同时只允许一个有效执行责任绑定。

## 宿主操作

检查当前环境能否列项目、创建项目、改名、移动会话和跳转，按已有授权逐项执行并记录结果。MCP 负责关联及命名意图，宿主工具执行实际操作，工作区工具管理 Git 和目录。只有真实返回的目标 ID 才登记为已创建。

创建和移动以稳定 operationId 记录 pending、succeeded、failed 或 unsupported。重试先核对已经成功的项目及序号，部分失败保留成功结果。宿主缺能力时提供可复制名称及人工绑定指引。新增会话或文件夹按任务授权范围进行。

## 补充事项

原验收所需的普通调试、重试和小修复保留在原步骤内。独立目标、单独安排或验收的事项经实际工具 `workbench_record_supplement` 登记，使用 create、update、linkPlan、resolve、cancel 等 schema 支持的动作。

记录来源步骤、目标、是否阻塞来源、状态及旧 repairId。旧 RepairCase/RepairAttempt 作为历史引用保留，含义不明的案例先待人工分类。

新事项进入待确认，用户确认规划后进入待规划。方案形成并取得执行范围授权后进入执行中，交付及验收满足后 resolve。取消需原因、替代或承接说明。阻塞事项创建与来源阻塞同步，完成或取消后解除对应阻塞来源，再检查原步骤全部前置与验收。

独立事项规划会话先展示一句目标、来源和阻塞说明，按用户现有授权推进。仅授权写方案时完成规划及可审阅交付，实施范围单独依据用户指令判断。
