# 执行状态、回执与接续

日期：2026-11-10

状态：Skill 操作规则

## 开始本次执行

读取当前方案、服务快照和台账，检查本次范围、绑定版本、真实目录与分支、全部必要前置及验收要求。前置不满足时保留待执行并列出等待对象。已获授权且前置满足时，登记逻辑执行开始与当前步骤进入执行中，保存服务返回的 executionId、版本及事件键。

工具不可用时把开始记录为待同步，按用户授权和本地可核实前置推进允许的工作。将服务门禁、发布确认或绑定确认要求列为等待条件。开始登记与步骤 running 使用同一逻辑事件的适配或分别关联，避免重复建立执行批次。

## 五状态更新

| 变化 | 上报依据 |
|---|---|
| 待执行 → 执行中 | 有效执行与绑定，全部必要前置满足 |
| 待执行 → 已取消 | 原因及后继影响处理 |
| 执行中 → 已阻塞 | 原因、等待对象、恢复条件 |
| 执行中 → 已完成 | 验收检查、结果与证据 |
| 执行中 → 已取消 | 原因及未完成事项 |
| 已阻塞 → 执行中 | 全部阻塞来源解除，重新检查前置 |
| 已阻塞 → 已取消 | 原因及后继处理 |
| 已完成或已取消 → 待执行或执行中 | 显式 reopen、原因及后继影响，进入执行中需重检前置 |

使用实际发现的 `workbench_update_step_status` 或语义一致的旧接口。状态值按 schema 映射 pending、running、blocked、completed、cancelled。普通调试、小修复及自动重试留在执行中，进展说明按需要追加。必要前置被取消时核对替代承接，完成阻塞分支后重新核对来源步骤。

完成前检查逐项验收，检查未执行或证据不足时保留待核验说明和实际业务状态。服务端规则判定有效完成，状态请求成功与验收证据分别记录。

## 同步和结束

### 验收与交接对应

更新日期：2026-11-10

五状态、验收记录、执行结束原因及 A—G 结论分别保存。代码交付后必要验收未完成时，保留执行中并记录待核验，交接选 B；需要外部条件且无法继续时登记阻塞。验收发现缺陷继续原步骤修复，选 A；原步骤已完成时显式 reopen。本站验收通过后提交 completed，等待其他线前置时选 C，下一站全部前置满足时选 D，实际开始后再将后继更新为 running。

等待用户时记录确认对象和解除条件，已开始且无法继续的步骤进入 blocked，未开始步骤保留 pending。验收确认选 B，范围或方案冲突选 G，其他情形按本站条件判断。一次聊天或执行结束时按实际状态提交回执，任务线全部条件满足选 E，项目全部条件满足选 F。A—G 依据全局范围核对。

必要用户体验确认列入验收要求。成功保存后回读步骤及证据，分别记录提交结果与验收依据。

每次逻辑操作建立稳定事件键，重试复用原键。请求已发送但结果未知时先查询或重放原请求。工具明确拒绝时记录原因，读取新版本或补齐问题后建立相应新操作。撤销授权后停止该授权下的新写入，保留可用范围内的本地交接资料。

结束本次执行时提交一次逻辑结束回执，包含完成本次范围、等待用户、阻塞、失败或取消等实际原因，附交付物、逐项验收、证据、未决项和相关步骤快照。快照携带当前版本，由服务校验并行更新。按通用模板输出完整回执，实际执行批次和整个方案的完成状态分别记录。

## 接续与中断

新会话先读取现有版本、原绑定、执行和未确认事件。跨会话继续同一次执行时沿用 executionId，重新核对责任绑定。接手建立有效新绑定，迟到结果按历史待核对处理。

异常中断后的结束时刻和结果依据已有证据补记，未知项保留未知。界面最后更新时间或会话停止只能用于定位核对范围。未到达服务端的事件由本地待同步记录恢复。
